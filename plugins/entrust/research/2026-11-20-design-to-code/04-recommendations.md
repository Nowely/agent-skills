# Independent recommendations after real-card calibration

This is Astra's independent assessment of the local calibration and current checker, reconciled with a separate replay of its synthetic counterexample. It contains proposals for the next edition. The original task was to evaluate the instrument before running another model comparison. The checks here used previously selected cases. They do not show a speedup or establish a pixel-perfect score.

## What worked

| Observation | Evidence and limit |
|---|---|
| The checker detects a real displaced visual landmark when told what to measure. | For one narrow card, an independently specified logo box was reported 3 px left and 15 px above its design position. The selector and design box were supplied manually. This does not establish automatic asset discovery. |
| A repeated-text self-comparison exposed a concrete tool defect. | The same rendered list and image originally produced zero differing pixels but 18 reported text findings at each of two widths. After matching whole snapshot text nodes in document order, the same self-comparison produced zero findings. This is evidence that this specific false-positive class was repaired. |
| An explicit alignment group found the known bad version. | The same grouping reported deviations at both widths for the already-known misaligned submission. The group was provided by the evaluator; the checker did not independently infer the header–value relationship. |
| A real design frame can be accessed through the existing MCP connection. | The metadata and PNG were obtained without a personal access token. A 601 × 145.09 CSS px frame rendered as a 601 × 146 px PNG. The metadata alone did not contain reliable displayed characters for most extracted text layers. |
| Test and safety feedback improved the implementation. | The current browser suite covers pending and missing evidence, the proposed-text case, repeated text, markup-split text, and restoring recorded Git edits in a disposable clone. A partial Git snapshot now reports omitted large files; non-Git snapshot recovery remains unavailable. |

## What remains weak

**The positive/negative gate has not passed.** The bad build produced alignment failures at 601 and 624 px. One previously accepted control passed both alignment checks. The other passed at 624 but failed at 601 with a spread of 1.015625 px against the built-in 1 px rule. Without a verified design-derived geometry, this case is **unresolved**: the earlier acceptance makes it a useful candidate control, not proof that every value and visual detail is correct.

The alignment results above refer to the sweep alone. All six complete frame comparisons returned fail, with 12 frame findings each. Consequently, “the control passed” must never be read as a full visual-parity verdict. In a separate comparison using a snapshot of the defective build as the visual reference, the repaired builds differed from that snapshot. Those pixel and landmark differences are observations, not evidence that either repaired build is wrong.

**A group of aligned boxes can still convey the wrong fact.** The current alignment probe measures the spread of visible DOM element edges selected by one CSS selector. The calibration's selector included the heading and values, so shifting only the values would be observable. But swapping contents while leaving boxes in place, or moving the entire heading and all values together, can preserve edge alignment while changing meaning or position relative to the design. If fewer than two visible elements match, the probe emits no alignment finding. These are code-backed limits; no complete detector of these scenarios was evaluated here.

**The exception limit is currently unsafe for sweep alignment.** A synthetic check passed an accepted entry capped at 1.02 px together with two measurements, 1.02 px at one width and 8 px at another. The grouped result classified both as accepted. The current probe emits textual alignment distances without a numeric delta, ledger matching does not apply max when delta is absent, and the sweep groups by property and selector before classifying. This is a demonstrated behavior of the current functions. Do not treat a bounded accepted entry as evidence that every width stayed inside its bound.

**The reference may be incomplete even when a tool call succeeds.** Twelve of fourteen extracted text landmarks in the sampled frame used generic layer names. In a local inspection, all 14 IDs mapped to one design-context element each. Twelve had direct plain text, one had text in a descendant, and one contained a JSX string literal. This suggests a node-ID join is feasible for this one frame. The displayed characters, nested geometry, scale handling and behavior on other frames have not been independently validated.

## Recommended sequence

1. **Create an independent answer key for one real frame.** Ask an owner or designer to inspect the design and anonymized captures at the same content, state, width and scale before seeing checker output. Record which labels belong to which values and classify visible differences as defect, accepted design-system difference, measurement error or unresolved. Include both accepted-looking and deliberately incorrect variants. Do not derive the key from the checker itself.
2. **Prove the reference path for that frame.** Match metadata nodes and design-context text by node ID, then visually validate the characters and frame-relative coordinates against the PNG. Check nested offsets, fractional sizes and exported image scale. Keep each unresolved landmark open. Test the existing MCP route without requiring a personal token; there is no reason yet to make automatic joining a new mandatory runtime dependency.
3. **Protect bounded exceptions before relying on them.** If the tool is to accept a numeric limit for a sweep finding, retain the actual numeric distance per width and classify each measurement before combining ranges. Add a regression where the small permitted difference remains accepted and a larger difference under the same selector remains visible. Also report a group that matched fewer than two visible elements. Until then, keep the borderline case for human review rather than silencing the group in the ledger.
4. **Choose tolerance from evidence and freeze it before the next control run.** Measure repeated renders and independently approved examples at the same width and scale. Test a legitimate fractional layout, an incorrect arrangement with the same boxes, missing matches, and measurements immediately below, at and above the chosen limit. Use a held-out case where possible. Do not change the threshold solely to make one preserved control pass.
5. **Only then run one short worker pair.** The same source, design inputs, permissions, budget and feedback policy go to both arms. Count first-submission quality, returns, worker and reviewer time, MCP calls and token usage. Compare outcomes as well as checker findings. One pair is a case observation, and meaningful generalization requires another unseen task.

The gate can move forward when a frozen, independently checked reference exposes the registered defects, verified controls stay within an owner-agreed false-alarm budget, and no unresolved observation changes the verdict. An alternative is to use the measurement report as an aid to human visual review while the automated gate remains open. Arc restoration remains separate until a disposable staged, unstaged and untracked round-trip succeeds.
