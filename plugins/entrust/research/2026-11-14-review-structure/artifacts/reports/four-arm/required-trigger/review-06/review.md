# Ревью диспетчера резервирований

**Исправить на месте.** Контракт валидации ID не выполняется для `cancel` и `has`; недостаток существовал до изменения, но относится к требованиям задания. Проверка идентичности записи таймера дублирует гарантии переданного `clock`.

1. **Поведение:** на открытом desk `cancel('')` и `has(1)` возвращают `false` вместо `TypeError` (`desk.js:29-38`, `case/brief.md:3`). Проверять ID в обеих операциях, сохранив `false` для `has` после закрытия.
2. **Необходимость:** проверка `active.get(id) !== entry` и объект `entry` не нужны при заданных гарантиях отсутствия синхронного вызова и отмены недоставленного таймера (`desk.js:17-20`, `case/brief.md:9`). Можно хранить непосредственно handle, проверяя наличие через `Map.has`, поскольку handle может быть ложным значением.
3. **Тесты:** `desk.test.js:106-114` проверяет неверные аргументы только для `reserve`; добавить некорректные ID для `cancel` и `has`, включая граничное поведение после закрытия.

Проведено только статическое ревью. Тесты, приложение, сборка и сеть не запускались по условиям задания; фактическая точность доставки зависит от реализации `clock`.
