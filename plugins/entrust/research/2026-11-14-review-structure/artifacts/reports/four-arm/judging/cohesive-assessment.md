## Общий источник истины, независимо проверенный по коду

### Обязательное поведение

Статическая трассировка подтверждает отсутствие известного обязательного дефекта:

- `src/round.js:9-15` выполняет replay до остальных guard, сравнивает `table`, `home`, `away`, игнорирует `expectedRevision`, возвращает прежнюю квитанцию без записи и выдаёт `ID_REUSED` при изменении payload (`brief.md:31-36`; тесты `test/acceptance.test.js:23-53`).
- `src/round.js:16-24` для нового ID соблюдает `ROUND_SEALED → STALE_REVISION → UNKNOWN_TABLE → TABLE_RECORDED → INVALID_SCORE` (`brief.md:37-43,65-66`; тесты `test/acceptance.test.js:64-94`). `Number.isInteger`, диапазон и неравенство исключают NaN, бесконечности, дроби, отрицательные значения и ничьи; границы 0 и 99 допускаются.
- `src/round.js:25-29` создаёт замороженную квитанцию со следующей ревизией, один раз вызывает `persist`, затем обновляет Map и revision. Исключение не перехватывается и возникает до публикации (`brief.md:27-29,45-47`; тесты `test/acceptance.test.js:96-133`).
- `src/round.js:32-34` реализует идемпотентный seal без persistence и изменения revision; replay стоит перед seal guard, а новые ID после seal блокируются (`brief.md:37,49-51`; тесты `test/acceptance.test.js:35-62`).
- `src/round.js:25,36-41` защищает состояние заморозкой квитанций и копированием snapshot; Map сохраняет порядок принятия (`brief.md:53-56`; тесты `test/acceptance.test.js:135-149`, `test/receipt.test.js:5-17`). Каждый вызов `createRound` создаёт независимое состояние (`src/round.js:1-5`; `test/acceptance.test.js:151-159`).
- Base действительно уже имел Map, revision, freeze и persist до публикации, но не имел replay, expectedRevision, table occupancy и seal. `test/round.test.js` и `package.json` в diff не изменены. Это подтверждает описания базовой совместимости в отчётах, но не заменяет запуск тестов.

Вывод рубрики об отсутствии обязательного дефекта поэтому **supported независимым чтением source**, а не принят на веру. Дополнительные async/reentrant-требования и валидация доверенных входов конструктора **not applicable** по `brief.md:10-23`; ни один отчёт их не навязывает.

### Что именно представляет собой `receipt(id)`

`src/round.js:40-42` — безэффектный прямой поиск в существующей Map, возвращающий замороженную квитанцию либо `null`; отдельный тест проверяет этот дополнительный API. Brief требует replay и snapshot, но не называет такой метод. При этом:

- replay требует исходные `table/home/away` (`src/round.js:9-15`);
- `snapshot().results` всё равно позволяет найти квитанцию по `id` без исходного payload и без записи, ценой копирования снимка и перебора не более 32 результатов (`src/round.js:36-38`, `brief.md:10,53-56`);
- прямой метод убирает этот перебор и задаёт собственный `null`-контракт.

Следовательно, и сохранение, и удаление метода вместе с его отдельным тестом технически совместимы с обязательным контрактом. Удаление теряет **прямой** поиск, но не саму возможность поиска по ID через snapshot. Потребность, частота использования и внешние потребители **unknown**. Нет source-основания называть метод функциональным дефектом или обязательным исправлением; есть обоснованная необязательная scope-альтернатива. Это согласуется с рубрикой (`RUBRIC.md:16-26,53-56`), но выведено также из API и эффектов source.

### Независимо подтверждённый тестовый пробел вне ожидаемого списка рубрики

Замечание ревью 01 и 03 о replay-квитанции **supported**. `test/acceptance.test.js:135-149` пытается мутировать первоначально возвращённую квитанцию и snapshot, но результат replay только сравнивает. Возможен регресс, при котором первый вызов возвращает защищённую копию, а replay — изменяемый внутренний объект: текущие проверки пройдут до попытки мутировать этот replay-результат, хотя последующая мутация нарушит `brief.md:53-56`. Текущий `src/round.js:9-15,25` такой дефект не содержит — обе ветки возвращают один замороженный объект. Это конструктивное усиление регрессионного покрытия, не доказательство неработающего head и не безусловно обязательное изменение кода.
