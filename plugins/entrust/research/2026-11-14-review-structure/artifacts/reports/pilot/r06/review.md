## 1. Старый callback может снять новую подсветку при повторном handle

behavior; read; `store.js:11`

Идентичность операции определяется handle планировщика. Контракт не гарантирует уникальность handle после clear. Если при повторном flash планировщик вернёт тот же handle, старый callback пройдёт проверку, снимет подсветку и удалит новую запись; новый callback затем не восстановит её. Это нарушает явное требование к старым callback.

Подтверждение: brief.md: повторный flash и контракт scheduler; store.js:8-15: clear старого handle, set нового и сравнение по handle. При последовательности set → clear → set с одним handle, затем вызове сохранённого старого callback guard пропускает его.

Исправление: Хранить отдельную идентичность каждой операции и проверять её в callback; handle использовать только для clear.
