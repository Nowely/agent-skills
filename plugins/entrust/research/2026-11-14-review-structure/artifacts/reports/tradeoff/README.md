# Synthetic tradeoff reports

This export contains **12 synthetic reviewer pairs (24 files)**: eight initial and four follow-up. Each pair contains `review.md` and `review.json`, not two independent model runs or an evaluation. Four historical synthetic assessments and two synthetic rubrics, originally hidden from reviewers, are included separately. No new experiment was performed. No real case, real report, source run map, or session identifier is published.

## Provenance and interpretation

See [manifest.json](manifest.json) for every pair, case, initial arm and repetition, source category, and per-file original/published SHA-256. Initial labels reproduce the non-real entries in the initial run map. Follow-up `report-1` and `report-2` are arbitrary labels sorted by source run ID within each case: they do **not** indicate arm, original repetition, or pairing. The follow-up run map does not record arm or repetition, so both are `null`. Source run IDs and session IDs are omitted; the original hashes allow comparison if the synthetic source is available.

Reviewer Markdown and JSON were copied byte-for-byte, with **no content substitutions**; original source directory names were replaced in this export by the labels above. Synthetic example identifiers, relative source paths, Git hashes, and diff hashes remain where present because they are part of the evidence; they are not session identifiers. References inside reports describe the original case layout and are not all clickable links from this export.

## Inputs and Git range

[cohesive](fixtures/cohesive/) and [tangled](fixtures/tangled/) contain the checked synthetic base and head file snapshots and a generated `change.diff`; `tangled/brief/` additionally contains the separate synthetic brief and acceptance file. The cohesive brief is inside `head/` and `base/`. Input files were taken from one synthetic run per case after checking that all 12 working-tree fixture copies match per case. Base files were read directly from the synthetic parent commit. `change.diff` is a read-only Git diff, not a new experiment.

Each fixture includes a `history.bundle` with its original two-commit synthetic Git history. A local clone of either bundle makes its recorded hashes and `HEAD~1..HEAD` resolvable; the plain snapshot directories themselves are not Git repositories. In each of the 12 source copies, the only ref was the synthetic branch, every stored object was reachable from HEAD, and no object alternates were configured. Raw commit headers contain only tree, parent where applicable, placeholder `Fixture` author and committer, timestamps with UTC offset `+0300`, and `base`/`head` messages. Those original identities and timestamps are retained in the bundles to preserve the commit hashes. Every reachable blob was checked against the published snapshots; all tree entries were regular files. Both bundles were locally cloned, checked with `git fsck`, and compared against the saved diff. The separate tangled brief is outside its Git history and must be taken from `fixtures/tangled/brief/`. The bundles do not recreate the model environment or reviewer execution.

## Assessments and limits

The four documents in `assessments/` are the available initial and follow-up assessments for the two synthetic cases. They are historical assessments, not newly performed judgments. The two files in `rubrics/` are synthetic evaluator rubrics; their original warning not to show them to reviewers describes the historical blind procedure, not a prohibition on this authorized export. Publishing them means these fixtures should not be treated as unseen benchmarks. The initial tangled evaluation explicitly identifies the included `tangled-v4` rubric; the follow-up tangled assessment cites matching rubric sections but does not itself identify its source path. The earlier, different tangled rubric is not included.

Source run IDs and machine-specific paths in the assessments were replaced with neutral case/arm/repetition labels or `review-labels/` references. The manifest records the substitutions and the follow-up evaluator-label mapping to published report pairs. That mapping was obtained by matching **both** Markdown and JSON bytes against the evaluator input copies, not by inferring arm or repetition. Consequently, the follow-up assessment for each case covers two initial candidate reports as well as two follow-up reports; it is not an assessment of four new follow-up runs. The shared evaluation template and other unreviewed materials are not included. Reported test outcomes and checks remain historical claims, not fresh verification.

Each report, assessment, rubric, and candidate input was subjected to pattern checks for local absolute paths, email addresses, URLs, common credential/session patterns and machine identifiers; review JSON was parsed. Reviewer Markdown and the published rubrics were individually read. The obvious `sk-reminder` substring in the synthetic package name `desk-reminder` is not a credential. These checks cannot prove the absence of all personal information or secrets. No real-case material was inspected for this export. The publication excludes skills, private maps, telemetry, and other unreviewed inputs.
