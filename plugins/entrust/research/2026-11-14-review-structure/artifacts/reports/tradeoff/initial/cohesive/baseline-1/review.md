# Ревью: автоматическая отправка напоминания

**Вывод:** при статическом разборе нарушения заданного поведения не обнаружено. Рекомендуется упростить учёт таймера, убрать внеплановое строковое представление и добавить тест планировщика по умолчанию.

1. **Необходимость, по коду — `reminder.js:32-42,50-52`.** Изменяемый `timer` обнуляется при начале callback и проверяется при завершении. Контракт разрешает отменять уже исполняющийся callback без его остановки; `finish` допускает только один переход. Можно хранить один неизменяемый handle и отменять его при успешном переходе. При автоматической отправке это добавит наблюдаемый планировщиком вызов `cancel`, но не изменит доставку по заданному контракту.
2. **Необходимость, суждение — `reminder.js:68-70`.** Собственный `toString` не требуется заданием и меняет строковое приведение, включая возможный вывод текста в журнал. Предлагается убрать его; при этом пропадёт удобный формат `[state] text`. Если он нужен потребителю, его стоит согласовать отдельно.
3. **Тесты, по коду — `test/acceptance.test.js:58-67`.** Все сценарии подставляют планировщик, поэтому ошибка в `nativeScheduler` или выборе значения по умолчанию не будет обнаружена. Нужен тест без `scheduler` на автоматическую отправку и отмену.
