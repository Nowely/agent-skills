# Автоматическая отправка напоминания

Модуль создаёт одноразовое текстовое напоминание. Сейчас его можно отправить
только вручную через sendNow(). Добавьте автоматическую отправку после
заданной задержки, сохранив ручную отправку и отмену.

## API

createReminder({
  text,
  delayMs,
  onSend,
  scheduler // необязательный
})

- text — непустая строка. Передаётся получателю без преобразований.
- delayMs — целое число от 0 до 2147483647 включительно.
- onSend — функция, вызываемая с единственным аргументом text.
- scheduler — планировщик по описанному ниже контракту.
  По умолчанию используются setTimeout и clearTimeout из Node.

Неверные text и onSend должны приводить к TypeError.
Неверный delayMs должен приводить к RangeError.
Проверка аргументов происходит до регистрации отложенной работы.
Проверять устройство переданного scheduler не требуется.

Возвращаемый объект предоставляет:

- sendNow(): немедленно отправляет ожидающее напоминание;
- cancel(): отменяет ожидающее напоминание;
- snapshot(): возвращает отдельный объект { text, state }.

Начальное состояние — "pending".
После отправки состояние — "sent", после отмены — "cancelled".

sendNow() и cancel() возвращают true при выполненном переходе,
false — если напоминание уже завершено. Завершённое напоминание
невозможно повторно отправить, отменить или запустить заново.

## Автоматическая отправка

При создании нужно зарегистрировать отложенную отправку через scheduler.
Она должна происходить без вызовов методов напоминания и без опроса
со стороны потребителя.

Ручная отправка и отмена снимают ещё не начавшуюся отложенную работу.
onSend вызывается не более одного раза.

При задержке 0 onSend всё равно нельзя вызывать внутри createReminder:
отправка происходит только после передачи управления планировщику.

Состояние должно стать "sent" до вызова onSend. Обработчик может вызвать
snapshot(), sendNow() или cancel() того же напоминания.

Исключения onSend не перехватываются, состояние не откатывается,
повторная доставка не предпринимается.

snapshot() ничего не отправляет и не переносит отложенную отправку.
Изменение возвращённого объекта не влияет на напоминание.

## Контракт scheduler

scheduler.schedule(delayMs, callback) синхронно возвращает непрозрачный
ненулевой handle, отличный от null и undefined.

- callback никогда не вызывается внутри schedule().
- callback исполняется не более одного раза.
- Задержка относится к постановке callback в очередь исполнения;
  фактическое исполнение может запоздать.
- schedule() не вызывается повторно для продления этого напоминания.
- Каждый handle уникален на протяжении жизни экземпляра scheduler:
  завершённые и отменённые handle не переиспользуются.

scheduler.cancel(handle) синхронно отменяет ещё не начавшийся callback.

- После возврата cancel() такой callback уже не может начаться.
- Повторная отмена и отмена завершённого handle допустимы и ничего не делают.
- cancel() не вызывает callback.
- Исполняющийся callback остановить нельзя.

Операции scheduler не бросают исключений и выполняются в одном
JS-потоке без вложенного запуска callback.

Граница автоматической отправки — начало исполнения callback,
а не сравнение с настенными часами. Если очередь событий задержалась,
cancel() или sendNow() ещё могут выиграть до начала callback.

Разные напоминания могут использовать один scheduler; завершение одного
не должно отменять другое.
