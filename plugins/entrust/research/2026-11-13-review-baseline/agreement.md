# Carbon agreement

Carbon (`openrouter/google/gemini-4-carbon`, requested high effort) reviewed the generic draft, report-data contract and release plan through OpenCode/OpenRouter. No private source or identifiers were supplied for this consultation. Both completed invocations had verified matching handbacks and attributed receipts.

The first review supported the design subject to four corrections:

1. Carry owner-accepted tradeoffs into refutation and include mechanisms in the finalized map.
2. Use a meaningful coordination mechanism in the example and permit empty/omitted unit links for file/config-level mechanisms; findings are optional.
3. Handle regional language codes and read back the saved record for mixed user-facing language.
4. Bump all release metadata together and distinguish the tested drafts 20/21/22 from unbenchmarked draft 23.

The revised documents incorporated those corrections. The example uses bounded import retries with references that exist in the example, rather than introducing an undefined form unit. Duplicate report guidance was removed to fit the installed skill's compaction limit; the always-read data contract retains the duties. Carbon then explicitly approved the revised candidate with no remaining release blockers.

Agreement concerns design/document consistency, not measured behavior or architectural superiority. Carbon did not run a new cohort, inspect the final JavaScript diff or validate the live installed plugin. The coordinator's offline tests and exact-head CI cover the executable release candidate.

Deferred suggestions: merge purpose/benefit if real reports demonstrate duplication; consider richer frozen-input support only if existing source-preservation instructions prove insufficient. Neither adds a new flag, mode or experiment to this release.
