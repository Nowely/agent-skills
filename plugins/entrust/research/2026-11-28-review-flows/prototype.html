Flows on a real change: entrust 0.48.0

Three flows drawn by hand from the skill's own code at 835c58d, the way a reviewer would write them into the record. Places, code lines and test names are real. Ran means the named test passed when its suite was run on 835c58d on 28 Nov; Read means only the code was read.

Ran: a named test asserts it Read: the code was read; nothing asserts it Proposed: what should happen, not run Question: the review could not settle it Not reached: should get here and does not

What a flow shows that a list does not

  • Forks and ends: in the data path, the reason reaches three readers and stops before the owner.
  • Evidence on each step and trigger, so a gap shows where it is.
  • Where gaps go: most to the author as tests, the rest to a person as a check with a recorded result.

When the list is enough

  • A straight path of three steps or fewer.
  • The check here reads as well as a checklist; the flow only adds the shared setup.
  • States read best as a table when every trigger needs its evidence; switch to List on the viewer.

What stays the same

  • Every step names a block or a place; one that names neither is drawn as Proposed.
  • Ran names the test and where it ran. The list of triggers is the reviewer's, so no ratio is shown as coverage.
  • Selecting a step opens its context; the whole flow stays in view.
