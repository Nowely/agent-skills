1. **[P1] Malformed CSV is accepted and can leave partial writes.** The quote scanner never rejects an unclosed quote or a quote in the middle of a field, and contacts are written as each line is processed. For example, a valid row followed by `"unclosed` leaves the first contact saved even though the file cannot be parsed. Parse the entire file before writing; the existing `parseCsv` already reports these syntax errors. [import.js:29](<target/src/contacts/import.js:29>)

2. **[P1] Quoted multiline records are split into separate rows.** Splitting on `\n` before interpreting quotes loses the record boundary. A name such as `"Ann\nSmith"` is rejected or misread, and subsequent rejections can receive the wrong physical start line. The existing CSV parser handles multiline fields and records their start lines. [import.js:13](<target/src/contacts/import.js:13>)

3. **[P1] Email validation differs from the address book.** This regex accepts `ann@site` and `a@b@site.test`, while the existing `isEmail` rejects both. Such rows are imported instead of reported as rejected. Reuse the existing validator. [import.js:1](<target/src/contacts/import.js:1>)

4. **[P1] Valid contacts at `example.invalid` are silently discarded.** The existing email validator accepts `ann@example.invalid`, but this branch neither imports nor rejects it. The test explicitly expects behavior contrary to the requested validation rule. [import.js:72](<target/src/contacts/import.js:72>)

5. **[P1] Duplicate emails are counted more than once.** A new email appearing twice increments both `created` and `updated`; an existing email appearing twice increments `updated` twice. The final name is correct for valid rows, but the returned counts violate the one-contact-per-email requirement. Deduplicate valid rows by normalized email before applying them. [import.js:76](<target/src/contacts/import.js:76>)

6. **[P2] Whitespace-only rows disappear.** `line.trim() === ""` skips a line containing spaces, although it is a row and must be rejected with its physical line number. Only a physical line with zero characters should be skipped. [import.js:21](<target/src/contacts/import.js:21>)

7. **[P2] Strict mode stops on a rejected row.** Passing `{ mode: "strict" }` throws instead of reporting the row and continuing; any earlier writes remain. The requested behavior has no exception for a mode, and the added strict-mode test codifies the opposite behavior. [import.js:58](<target/src/contacts/import.js:58>)

8. **[P2] Insert failures are swallowed.** After three failed insert attempts, the importer silently skips a valid contact and returns a successful-looking result without recording a rejection or exposing the error. A persistent store failure therefore causes data loss from the caller’s perspective. [import.js:83](<target/src/contacts/import.js:83>)

The import tests cover only a simple happy path and rejection count; they do not verify stored names, duplicate counts, malformed-file atomicity, multiline records, whitespace-only rows, or the existing email-validation boundary. This was a static review; the code and tests were not run.
