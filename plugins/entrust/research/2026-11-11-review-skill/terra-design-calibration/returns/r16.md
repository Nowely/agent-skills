## Change

Adds a named `previewEdit` export that decides whether a booking edit is blocked, unchanged, or ready, and builds a priced update command.

Parts: catalog lookup and comparison; quote calculation; decision precedence; result construction.

Sources: task in `brief.md`; input and pricing contracts in `README.md`; existing creation flow in `src/bookings/create.js` and `src/bookings/quote.js`.

Requirements:

1. Return `forbidden` without edit access, before all other decisions — task; **met by tracing**.
2. Return `closed` for a cancelled booking, before unchanged and validation decisions — task; **met by tracing**.
3. Return `unchanged` when the four edit fields match, even if the room has disappeared or capacity changed — task and `README.md:21`; **met by tracing**.
4. Block a non-positive interval, a missing room, and excess capacity, in that order — task; **met by tracing**.
5. Otherwise calculate setup charge plus hourly charge per started hour, and require confirmation only when the total exceeds paid cents — task; **met by tracing**, but duplicated pricing logic is finding 1.
6. Return exactly the specified result fields, preserving the revision and draft values — task; **met by tracing**.
7. Do not mutate inputs, persist, or contact a service — task and `README.md:22`; **met by tracing**.
8. Cover the new behavior against regressions — review requirement; **fails**, finding 4.

## Verdict

The decisions and result shapes match the task for the documented input boundary by static tracing. The implementation duplicates the existing pricing function, adds a cache that cannot hit, and expresses precedence through reversed, mutable state; there are no tests for the new flow.

Target: `previewEdit` performs ordered early returns, looks up the room after the earlier decisions, then calls the existing `quoteRoom` and constructs the ready result. Keep the comparisons and command fields; remove the local cache and intermediate decision state.

Recommendation: fix in place. First reuse the quote function and remove the cache (1–2), then express the decision order directly (3), and add behavior tests (4).

## Findings

### 1. Pricing duplicates the existing quote function (necessity; traced)

`src/bookings/edit.js:22`: the edit flow independently implements the same pricing rule as `quoteRoom`. A future pricing change must update both flows or they can quote the same room and interval differently, affecting requirement 5.

Shown by: `src/bookings/quote.js:1-2` implements the same formula; `src/bookings/create.js:7` already uses it. `README.md:30` specifies that its caller supplies an existing room and a positive interval.

Fix: call `quoteRoom(room, draft.start, draft.end)` after the room and interval checks.

### 2. The per-call quote cache can never hit (necessity; traced)

`src/bookings/edit.js:15-25`: each invocation creates an empty map, performs one lookup and at most one insertion, then discards it. Removing the cache does not change any result under the stable-input contract.

Shown by: the map is local and has no other reads or writes; `README.md:22` guarantees inputs remain stable during a call.

Fix: calculate the total once using `quoteRoom`, without a map or key.

### 3. Decision precedence is encoded backwards through mutable flags (design; judgment)

`src/bookings/edit.js:29-58`: lower-priority decisions run first and higher-priority decisions overwrite them, including resetting `unchanged`. Changing the task’s precedence or adding a decision requires reasoning about every later overwrite and reset, rather than reading the decisions in their specified order. This makes requirement 1–4 maintenance harder.

Shown by: the task lists `forbidden` first and capacity last, while the code assigns them in the opposite order. The existing `previewCreate` uses ordered early returns at `src/bookings/create.js:4-5`.

Fix: return each decision in task order, then calculate and return the ready result.

### 4. The new flow has no regression tests (tests; traced)

`src/bookings/edit.js:1`: no tests were added, and the repository contains no test files. Regressions in requirements 1–7 can therefore pass without detection.

Shown by: for example, returning `capacity` before `unchanged` when a saved room’s capacity has fallen, requiring confirmation when price equals paid cents, or changing `expectedRevision` would each go undetected.

Fix: add tests covering overlapping decision precedence, valid and invalid intervals, absent room and capacity boundaries, started-hour rounding, price below/equal/above paid, exact result shapes and input immutability.
