## Change

Adds CSV contact import: validate rows, select the last valid row per normalized email, then create or rename contacts and return counts and rejections.

Source: the task in `brief.md`.

Requirements:

1. Reject empty names and invalid emails with the physical starting line and reason; continue importing other rows. **Met by static tracing; boundary coverage is incomplete** ([2](#2-add-import-tests-for-row-boundaries-tests-traced)).
2. Identify contacts by email regardless of case and surrounding spaces; create new contacts and rename existing ones. **Met by static tracing.**
3. Count each email once; the last valid duplicate wins, and a rejected duplicate does not replace it. **Met by static tracing; regression coverage is incomplete** ([1](#1-cover-duplicate-results-and-rejected-duplicates-tests-traced)).
4. Return created and updated counts and rejected rows. **Met by static tracing; duplicate-count coverage is incomplete** ([1](#1-cover-duplicate-results-and-rejected-duplicates-tests-traced)).
5. Write nothing if parsing fails. **Met by static tracing.**
6. Ignore physically empty lines, retain space-only and incomplete rows, and use the record’s physical starting line. **Met by static tracing; import-level coverage is incomplete** ([2](#2-add-import-tests-for-row-boundaries-tests-traced)).
7. Use the address book’s existing email validation. **Met by static tracing.**

## Verdict

The implementation meets the stated behavior on the paths traced. The principal gaps are tests for explicit duplicate and CSV-boundary requirements.

Target: retain the parser, existing email validation and store; collect valid rows by normalized email before applying one operation per contact. The change already has this shape.

Recommendation: fix in place by adding the focused tests in findings 1 and 2.

## Findings

### 1. Cover duplicate results and rejected duplicates (tests; traced)

`test/import.test.js:15`: The duplicate test checks the plan for a new email, but does not check import counts for duplicates or a rejected row following a valid duplicate. Requirements 3 and 4 lack regression coverage.

Shown by: a regression that counts input rows instead of distinct emails, or removes an earlier valid entry when a later duplicate is rejected, passes the current tests.

Fix: test repeated new and existing emails through `importContacts`, including a rejected duplicate after a valid row; assert the final names, counts and rejection.

### 2. Add import tests for row boundaries (tests; traced)

`test/import.test.js:23`: The import test does not cover a space-only line, missing columns, a quoted empty field, or a rejected multiline record’s starting line. Requirements 1 and 6 lack import-level regression coverage.

Shown by: a change in the import path that drops space-only or incomplete records, or reports the ending line of a multiline rejection, can pass the current import tests. Parser tests cover some individual primitives but do not establish their result through import.

Fix: add an import test containing those rows and assert the rejection reasons and physical starting lines, alongside a valid row that still imports.
