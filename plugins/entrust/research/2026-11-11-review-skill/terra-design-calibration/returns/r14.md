## Change

Adds a named `previewEdit` export that decides whether a booking edit is blocked, unchanged or ready, and builds a priced update command.

Parts: access and state checks; unchanged comparison; draft and room checks; price and command construction.

Sources: task brief; `README.md` input and pricing contract.

Requirements:

1. Deny users without edit access with `forbidden` before other decisions — task; met by tracing.
2. Block cancelled bookings with `closed` — task; met by tracing.
3. Return `unchanged` when the four editable values match, before validating the draft or catalog — task; met by tracing.
4. Block equal or reversed intervals with `invalid-window` — task; met by tracing.
5. Block a selected room absent from the current catalog — task; met by tracing.
6. Block headcount above room capacity — task; met by tracing.
7. Otherwise return the exact ready shape, using the specified command fields and unchanged revision — task; met by tracing.
8. Charge setup once plus each started hour; require confirmation only above the amount paid — task and `README.md:3`; met by tracing.
9. Preserve inputs and perform no persistence or network work — task and `README.md:22`; met by tracing.

## Verdict

The implementation meets the specified behavior by static tracing, including decision order and pricing boundaries. The change has no tests, so regressions in those decisions and in the returned command would pass unnoticed.

Target: keep `previewEdit` as the single decision function, reusing `quoteRoom` for pricing. Add focused tests for its observable decisions, boundaries, output and input preservation.

Recommendation: fix in place by adding the tests in finding 1.

## Findings

### 1. The edit decisions and command have no regression tests (tests; traced)

`src/bookings/edit.js:3`: The new public function has no tests in the repository. Requirements 1–9 could regress without a test failing.

Shown by: the task calls `previewEdit` with the documented inputs; there are no test files or test scripts in the repository. For example, reversing the `forbidden` and `closed` checks, changing `>` to `>=` for price confirmation, or changing `expectedRevision` would go undetected.

Fix: add tests for decision precedence, unchanged bookings whose room has disappeared or lost capacity, equal and reversed windows, missing rooms, capacity equality and excess, started-hour pricing, prices below/equal/above the amount paid, exact result shapes, and unchanged inputs.
