## Change

Adds a named `previewEdit` export to preview booking edits, choose a decision in the specified order, and produce a price and update command without saving.

Parts: room lookup and comparison; quote calculation; ordered decision selection; result construction.

Sources: `brief.md`; `README.md`.

Requirements:

1. Deny users without edit access as `forbidden` — task; **met by tracing**.
2. Block cancelled bookings as `closed` — task; **met by tracing**.
3. Return `unchanged` when all four editable fields match — task; **met by tracing**, including when the saved room has disappeared or its capacity has changed.
4. Block non-positive intervals as `invalid-window` — task; **met by tracing**.
5. Block missing rooms as `room-unavailable` — task; **met by tracing**.
6. Block headcounts exceeding capacity as `capacity` — task; **met by tracing**.
7. Otherwise return the exact `ready` shape, with started-hour pricing and confirmation only for a strictly higher price — task; **met by tracing**. Pricing duplicates the existing quote function: finding 1.
8. Export the function, preserve inputs, and perform no persistence or service calls — task and README; **met by tracing**.

## Verdict

The implementation produces the required decisions and result shapes for the documented inputs by static inspection. It duplicates the existing pricing calculation, uses a cache that cannot have a hit, and has no tests protecting the decision order or results.

Target: use ordered early returns for the decisions, then call the existing `quoteRoom` once and construct the ready result. Keep the comparisons and command fields from the change.

Recommendation: fix in place. First reuse the quote function and remove the cache (1–2), simplify decision selection (3), then add contract tests (4).

## Findings

### 1. Pricing is duplicated instead of reusing `quoteRoom` (necessity; traced)

`src/bookings/edit.js:22` repeats the formula in `src/bookings/quote.js:2`. The two currently agree, but a pricing rule change can leave creation and editing quoting different prices, contrary to requirement 7.

Shown by: `src/bookings/create.js:7` already uses `quoteRoom`; `README.md:30` defines its existing-room and positive-interval prerequisites, both satisfied on the ready path.

Fix: call `quoteRoom(room, draft.start, draft.end)` after the blocking checks.

### 2. The per-call cache can never be hit (necessity; traced)

`src/bookings/edit.js:15` creates a fresh map, and lines 18–25 perform only one lookup and insertion before the function returns. The key and cache do not serve requirement 7.

Shown by: the map is local to `previewEdit` and there is no loop or second lookup in `src/bookings/edit.js:15–25`.

Fix: remove the map and calculate the quote once.

### 3. Decision precedence is encoded through reverse-order overwrites (design; judgment)

`src/bookings/edit.js:29` through `:58` selects decisions in reverse order and repeatedly resets three variables. Changing the task’s decision priority requires reasoning about later overwrites and the interaction between `blocked` and `unchanged`, rather than changing the order of the decisions themselves.

Shown by: requirements 1–6 can change in priority independently; their current implementation spans the assignments at `:29–55` and the returns at `:57–58`.

Fix: return each decision directly in the task’s stated order, as the existing creation flow does in `src/bookings/create.js:4–5`.

### 4. The new contract has no tests (tests; traced)

`src/bookings/edit.js:1` introduces the entry point without tests in the repository. Reversing the `forbidden` and `closed` priority, treating equal price as requiring confirmation, or dropping `expectedRevision` would pass the current test suite because no test exercises this function.

Shown by: the repository contains no test files, and `package.json` defines no test command.

Fix: add tests for competing decision conditions and the exact result shapes, including missing or changed saved rooms, invalid interval boundaries, capacity equality and excess, started-hour rounding, equal versus higher price, and input immutability.
