- **[P1] Некорректный CSV может частично изменить адресную книгу** — [import.js:25](target/src/contacts/import.js:25). Парсер не проверяет незакрытые или неверно расположенные кавычки, а записи сохраняются до разбора остального файла. Например, корректная первая строка будет записана, даже если следующая содержит незакрытую кавычку. Нужно сначала целиком разобрать файл существующим `parseCsv`, и только после успешного разбора менять store.

- **[P1] Корректные многострочные поля разбиваются на отдельные записи** — [import.js:13](target/src/contacts/import.js:13). Разделение по `\n` теряет состояние кавычек между физическими строками. Имя вроде `"Ann\nSmith"` импортируется неправильно, а последующие строки могут получить неверные отказы и номера строк. Существующий CSV-парсер поддерживает многострочные поля и номер начальной физической строки.

- **[P1] Повторяющийся email учитывается несколько раз** — [import.js:76](target/src/contacts/import.js:76). Если новый адрес встречается дважды, результат показывает одно создание и одно обновление, хотя по заданию адрес должен считаться один раз. Для уже существующего контакта каждое повторение также увеличивает `updated`. Нужно сначала выбрать последнюю валидную строку для каждого нормализованного адреса и затем применить её один раз.

- **[P1] Проверка email расходится с адресной книгой** — [import.js:1](target/src/contacts/import.js:1). Локальное выражение принимает, например, `ann@site` и `a@b@c`, хотя существующий `isEmail` их отклоняет. Такие строки ошибочно сохраняются и могут заменить предыдущий валидный дубликат. Нужно использовать `isEmail` из `contacts/email.js`.

- **[P1] Валидные адреса молча пропускаются по домену** — [import.js:72](target/src/contacts/import.js:72). `ann@example.invalid` проходит существующую проверку email, но не создаётся и не попадает в `rejected`. Это исключение отсутствует в задании; добавленный тест закрепляет неверное поведение.

- **[P2] Строки из пробелов не сообщаются как отклонённые** — [import.js:21](target/src/contacts/import.js:21). Условие пропускает любую строку после `trim()`, хотя пропускать требуется только физическую строку без символов. Например, строка из трёх пробелов должна получить отказ с её номером.

- **[P2] Ошибки сохранения скрываются** — [import.js:85](target/src/contacts/import.js:85). Любое исключение `insert` перехватывается трижды, после чего контакт молча пропускается. Вызывающая сторона получает успешный результат с неполным импортом и без причины. Существующий store не описывает временных ошибок, требующих повторов; ошибку следует передать вызывающей стороне.

- **[P2] Strict mode останавливает импорт на отклонённой строке** — [import.js:58](target/src/contacts/import.js:58). При `mode: "strict"` неверная строка вызывает исключение вместо добавления в `rejected` и продолжения, вопреки контракту. Тест strict mode проверяет это противоречащее заданию поведение.

Тесты не покрывают атомарность при ошибке разбора, многострочные поля, нормализованные дубликаты, несовпадение валидации и строки из пробелов. Код и тесты не запускались: проведено только статическое ревью.
