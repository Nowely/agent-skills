1. **[P1] Malformed CSV can leave contacts written.** [import.js:29](target/src/contacts/import.js:29) toggles quote state without checking for an unclosed or misplaced quote, and writes each row before parsing the rest of the file. A malformed later row therefore does not prevent earlier writes, violating the all-or-nothing parsing requirement. Parse the complete file before mutating the store; the existing `parseCsv` already detects malformed quoting.

2. **[P1] Valid multiline CSV records are split into separate rows.** [import.js:13](target/src/contacts/import.js:13) splits on physical newlines before processing quotes. A name such as `"Ann\nSmith"` is consequently rejected or misread, and subsequent line numbers can be wrong. The existing parser handles quoted line breaks and records their starting physical line.

3. **[P1] Import uses a different email validator.** [import.js:1](target/src/contacts/import.js:1) accepts addresses such as `ann@site` and `a@b@c`, which the address book’s `isEmail` rejects. Reuse `isEmail` so import and contact creation apply the same definition.

4. **[P2] Duplicate emails are counted more than once.** [import.js:76](target/src/contacts/import.js:76) processes and counts every valid row independently. Two rows for a new email produce one creation and one update, while two rows for an existing email produce two updates. Deduplicate valid rows by normalized email before writing and counting; retain the last valid row.

5. **[P2] Valid contacts at one domain are silently discarded.** [import.js:73](target/src/contacts/import.js:73) skips `ann@example.invalid` even though the existing validator accepts it. The row is neither imported nor reported as rejected. Remove this special case; the test asserting the skip contradicts the requested behavior.

6. **[P2] Insert failures are silently reported as successful imports.** [import.js:85](target/src/contacts/import.js:85) retries every exception three times and then continues without reporting the row or error. A store failure can thus lose a valid contact while returning normal counts. Propagate the failure instead of swallowing it.

7. **[P2] Strict mode stops on a rejected row.** [import.js:59](target/src/contacts/import.js:59) throws instead of reporting the rejection and continuing, potentially after earlier rows have been written. The task requires invalid rows not to stop import; the strict-mode test currently enshrines the opposite behavior.

The import tests also omit malformed-file atomicity, multiline records, duplicate counts and last-valid-row behavior, validation parity, and physical line numbers. Review was static; code and tests were not run.
