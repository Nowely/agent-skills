## Change

The nightly job emails customers about unpaid invoices after their UTC due date, marks successful sends, and retries failed sends. Source: `brief.md`.

Requirements:

1. Send after the due date has passed, only while the invoice is unpaid.
2. Include the invoice number, amount and due date.
3. Notify each invoice once.
4. Continue after a send failure and retry that invoice the next night.

## Verdict

The sequential flow meets the requirements, but overlapping runs can both send the same invoice before either marks it. The tests do not cover that case.

Target: keep the existing eligibility check, formatting, mailer and success marker. Coordinate runs using the same repository so a second run cannot make the same send decision while the first is awaiting delivery; retain retry after a rejected send.

Recommendation: fix in place, starting with finding 1 and its regression test.

## Findings

### 1. Overlapping runs can notify an invoice twice (behavior; traced)

`src/invoices/overdue.js:9`: Two `runNightly` calls sharing a repository can both observe an unmarked overdue invoice. The first yields at `mailer.send`; before it resumes and writes the marker at line 18, the second can send the same invoice. This breaks requirement 3.

Fix: coordinate overlapping runs against the same repository so the check, send and marker cannot be repeated concurrently, while preserving retry when sending rejects.

### 2. No test exercises overlapping runs (tests; traced)

`test/nightly.test.js:30`: The once-only test awaits the first run before starting the second, so it passes even when overlapping runs send twice. A deferred mailer can hold the first send open while a second run starts, then verify that only one message is accepted. This protects requirement 3.

Fix: add that regression test alongside the existing sequential test.
