1. **[P1] Ошибка разбора может оставить частичный импорт.** В [import.js](case/head/src/contacts/import.js:31) незакрытая или неправильно расположенная кавычка не считается ошибкой. Например, после корректной строки строка `Bob,"bob@site.test` будет импортирована, хотя файл некорректен. Записи также выполняются до проверки остального файла. Существующий `parseCsv` обнаруживает ошибки; весь файл нужно разобрать до изменений хранилища.

2. **[P1] Корректные многострочные поля разбиваются на отдельные строки.** Разделение по `\n` в [import.js](case/head/src/contacts/import.js:13) не учитывает перенос внутри кавычек. CSV с именем `"Ann\nSmith"` будет обработан как несколько записей; данные и номера отклонённых строк окажутся неверными. Существующий `parseCsv` поддерживает такие поля и возвращает номер начала записи.

3. **[P1] Повторный email увеличивает счётчики несколько раз.** В [import.js](case/head/src/contacts/import.js:76) каждая строка сразу записывается и учитывается. Для двух строк с новым одинаковым email результат будет `created: 1, updated: 1`, хотя контакт должен учитываться один раз как созданный. Для существующего контакта `updated` тоже увеличится дважды. Последняя допустимая строка должна определять итоговое имя, а счётчик — состояние до импорта.

4. **[P1] Допустимые строки молча пропускаются по домену.** Проверка в [import.js](case/head/src/contacts/import.js:72) исключает все адреса `@example.invalid`, не создавая контакт и не сообщая об отказе. В задании такого исключения нет; тест закрепляет это поведение.

5. **[P2] Проверка email расходится с остальным приложением.** Выражение в [import.js](case/head/src/contacts/import.js:1) принимает, например, `ann@site` и `a@b@c`, тогда как существующая `isEmail` их отклоняет. Импорт может создать контакты с адресами, которые форма создания не принимает; следует использовать общую проверку.

6. **[P2] Ошибки записи скрываются от вызывающей стороны.** В [import.js](case/head/src/contacts/import.js:85) любая ошибка `insert` перехватывается трижды, после чего строка молча пропускается. Результат выглядит успешным, хотя контакт потерян и не указан в `rejected`. Повторные попытки не различают причины ошибки; её следует передать вызывающему коду.

7. **[P2] Режим `strict` нарушает обработку отклонённых строк.** В [import.js](case/head/src/contacts/import.js:59) некорректная строка прерывает импорт исключением вместо включения в `rejected` и продолжения. Предыдущие строки при этом уже могли быть записаны. Задание не предусматривает такого режима; соответствующий тест проверяет поведение, противоречащее требованию.

Проверка статическая: код и тесты не запускались. Текущим тестам не хватает случаев с ошибкой CSV после корректной строки, многострочным полем, повторным email и адресами, проверяемыми общей `isEmail`.
