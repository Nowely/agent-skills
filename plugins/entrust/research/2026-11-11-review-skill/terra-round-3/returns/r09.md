## Change

The change attempts to uppercase invoice currency codes in the list, invoice page, and CSV export. It adds a currency normalizer, changes both screens, and adds tests.

**Source:** the supplied task in `brief.md`.

**Requirements:**

1. Show uppercase currency in the invoice list — **met by tracing** valid service and archive inputs.
2. Show uppercase currency on the invoice page while preserving the code — **fails**, finding 1.
3. Show uppercase currency in CSV — **fails**, finding 2.
4. Handle invoices from both the billing service and the closed local archive — **fails**, findings 1 and 2.

The task’s example suggests lower-case service currencies may occur, but the installed `@acme/billing-client` 2.3.0 rejects them; the archive contract explicitly permits lower-case codes.

## Verdict

The list uppercases valid codes, but the page can replace a valid currency with USD, and CSV still exports archive currencies in lower case. The new tests do not exercise either failing output.

**Target:** Uppercase `cur` when `readArchive` constructs an invoice; the service client already guarantees uppercase. Keep the existing shared `formatPrice` and screen implementations, and add tests covering the two sources and all three outputs.

**Recommendation:** Fix in place.

1. Preserve valid currency codes and cover CSV, findings 1–2.
2. Remove the unsupported fallback and exception handling, findings 3–4.
3. Test the actual source-to-output paths, finding 5.

## Findings

### 1. The page replaces valid currencies outside a three-code list with USD (behavior; traced)

`src/invoices/price.js:8`: `JPY` becomes `USD`, so an invoice for `JPY 10.00` is displayed as `USD 10.00`. This breaks requirements 2 and 4.

**Shown by:** `src/invoices/load.js:6` supplies both sources. `node_modules/@acme/billing-client/index.js:3` and `:11` accept `JPY`; `data/archive.schema.json:9` accepts `jpy`, which `src/invoices/archive.js:3` passes through. `src/screens/page.js:6` applies the whitelist. The new `test/price.test.js:20` also pins substitution for `xxx`, although the archive schema accepts that code.

**Fix:** Preserve the code and uppercase it; do not substitute USD for codes outside the list.

### 2. CSV leaves archived currency codes in lower case (behavior; traced)

`src/export/csv.js:2`: CSV writes `invoice.currency` unchanged, so an archived `usd` remains `usd`. This breaks requirements 3 and 4.

**Shown by:** The task explicitly names CSV. `src/invoices/archive.js:3` copies `row.cur`, and `data/archive.schema.json:9` specifies lower-case archive codes.

**Fix:** Uppercase archive currency when constructing the invoice, so CSV receives the uppercase code.

### 3. Missing-value handling and trimming have no supported input (necessity; traced)

`src/screens/list.js:4` and `src/invoices/price.js:3`: the USD fallback, non-string and empty checks, trimming, and configurable fallback address values excluded by both input contracts. The list comment cites documentation for client 1.x, while the application imports 2.3.0. The null tests pin a state neither supported source produces.

**Shown by:** `node_modules/@acme/billing-client/index.js:11` requires three uppercase letters; `data/archive.schema.json:5` and `:9` require three lowercase letters. `src/invoices/load.js:6` combines those sources.

**Fix:** Remove these checks and the null tests. Uppercasing the archive’s required string retains the requested behavior.

### 4. The page catches an error that supported invoices cannot produce (necessity; traced)

`src/screens/page.js:5`: the catch substitutes a fabricated `USD 0.00` price. Under the supported contracts, currency is a string and amount is an integer, so the operations inside the try do not throw.

**Shown by:** `node_modules/@acme/billing-client/index.js:11` and `:14`; `data/archive.schema.json:5`, `:9` and `:10`. Both feed the page through `src/invoices/load.js:6`.

**Fix:** Remove the try/catch and use the shared formatter as before.

### 5. Tests do not cover the page, CSV, or archive path (tests; traced)

`test/price.test.js:10`: the new test exercises the normalizer and list directly. A lower-case CSV regression or a page that displays `USD` for `JPY` passes the suite.

**Shown by:** The test imports neither `renderPage` nor `toCsv`, and does not construct an invoice through `readArchive` or `loadInvoices`.

**Fix:** Test an archive invoice through all three outputs, including a code outside the whitelist, and a service invoice against the same outputs.
