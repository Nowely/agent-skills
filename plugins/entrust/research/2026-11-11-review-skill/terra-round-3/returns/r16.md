## Change

Adds CSV contact import, using the existing parser and contact store.

Requirements from `brief.md`:

1. Reject rows with an empty name or invalid email; report line and reason and continue.
2. Match emails without regard to case or surrounding spaces; rename existing contacts and create new ones.
3. Count repeated emails once, with the last row winning.
4. Return created and updated counts and rejected rows.
5. Write nothing when parsing fails.
6. Ignore blank lines.

Source: `brief.md`.

## Verdict

The main import path meets most requirements, but it silently omits a nonblank CSV record containing one quoted empty field. The tests also do not verify duplicate counting through the public import function.

Target: retain the existing planner and import flow, and reuse the existing email and store functions. Correct the parser’s distinction between a blank line and an empty quoted field, and test both that case and duplicate counts through `importContacts`.

Recommendation: fix in place, starting with finding 1.

## Findings

### 1. An empty quoted record is silently dropped (behavior; traced)

`src/contacts/import.js:31`: For `name,email\n""\n`, the existing `parseCsv` treats the second line as blank because its only decoded cell is empty (`src/lib/csv.js:10–12`). The import consequently returns no rejection, although the line is a CSV record with an empty name. This breaks requirements 1 and 6. The parser already maps a missing cell to an empty string, so a single-field record is supported.

Fix: make the parser distinguish a physically blank line from a record containing a quoted empty field, and test that the import reports line 2.

### 2. Duplicate counts are not tested through import (tests; traced)

`test/import.test.js:15–29`: The planner test covers a repeated new email, while the import test uses distinct emails. An import that processes duplicate rows separately could therefore count one contact as both created and updated without failing these tests, breaking requirement 3.

Fix: test `importContacts` with repeated case- and space-varied emails, asserting the last name and a single created or updated count. Include an existing contact as well as a new one.
