## Change

The change uppercases archived invoice currencies before they reach the invoice list, invoice page and CSV export. Service invoices already have uppercase currency codes under the installed client’s contract.

Sources: `brief.md`, `git diff HEAD~1 HEAD`.

Requirements:

1. Show uppercase currency in the invoice list, for both service and archive invoices — task; **met by static trace**, with an integration test gap in finding 1.
2. Show uppercase currency on the invoice page, for both sources — task; **met by static trace**, with the same test gap.
3. Export uppercase currency in CSV, for both sources — task; **met by static trace**, with the same test gap.

The older `docs/billing.md:3-8` describes the 1.x client and contradicts the installed 2.3.0 client’s currency contract. The application imports the 2.3.0 client directly.

## Verdict

The implementation meets the requested behavior under the contracts checked. The new output test bypasses the actual invoice-loading entry point, leaving the integration between the two sources and the outputs untested.

Target: keep normalization in `readArchive`; reuse the billing client’s validation for service invoices and the existing list, page and CSV consumers. Exercise both sources through `loadInvoices` in an output test.

Recommendation: fix in place by addressing finding 1.

## Findings

### 1. The output test bypasses the invoice-loading path (tests; traced)

`test/outputs.test.js:9`: The test supplies invoices directly from `readArchive`, so it does not verify that the application’s combined loader delivers normalized archive invoices alongside service invoices.

Shown by: `src/invoices/load.js:5-6` is the entry that combines both sources. If it passed raw archive rows to the consumers instead of calling `readArchive`, all existing tests would still pass while archive prices and CSV rows would be wrong.

Fix: add an integration test that calls `loadInvoices` with a valid uppercase service invoice and a lowercase archive row, then checks the list, page and CSV results.
