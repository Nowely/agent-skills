## Verdict
The change does not meet its task. The CSV export is untouched and still prints "Shipped" for late orders, so the screen and the export now disagree. The delay rule also marks an order "Delayed" on its promised date, which the task says must still read "Shipped". Most of the added code (try/catch, `?? "unknown"`, `fallbackLabel`, a second label table) guards against inputs the contract rules out.

## Findings

### 1. CSV export not updated, so it disagrees with the screen (behavior; traced)
- Where: <run>/repo/src/orders/export.js:4, `statusLabel(order.status)`. The commit does not touch this file.
- What happens: any shipped order past its promised date is "Delayed" in `renderList` but "Shipped" in `toCsv`. Requirement 2 is missing.
- Evidence: export.js:1 and :4 still import and call `statusLabel` from labels.js. The diff changes only list.js, badge.js and the tests.
- Fix: have `toCsv` call the same function as `renderList`, passing `now` the same way, and add an export test.

### 2. Order is "Delayed" on the promised date itself (behavior; traced)
- Where: src/orders/badge.js:20, `promised < now`.
- What happens: `promisedAt` is a calendar date (contracts/order.schema.json:10), e.g. "2026-03-20". `new Date("2026-03-20")` is midnight UTC. On 2026-03-20 at 09:00Z, `promised < now` is true, so the order reads "Delayed" on the promised day. The task requires "Delayed" only from the day after.
- Evidence: the ES spec parses date-only strings as UTC. The fixture `now` in test/badge.test.js:5 is 09:00Z, so the same-day case would fail. No test covers it.
- Fix: compare calendar dates, not instants. For example, compare `order.promisedAt` with the `YYYY-MM-DD` of `now` as strings, since the contract guarantees that format. A shipped order is delayed when `promisedAt < today`. Decide and document which timezone "today" is in. `now.toISOString().slice(0,10)` is UTC, which may differ from the viewer's day.

### 3. Dead try/catch around `new Date()` (necessity; traced)
- Where: badge.js:15-19, `try { promised = ... new Date(order.promisedAt) ... } catch { promised = null; }`.
- What happens: `new Date(string)` never throws. An invalid string yields an Invalid Date, so the catch cannot run. The format is already validated as `YYYY-MM-DD` by `fetchOrders` (src/api/validate.js:19-20), and the task says orders reach the code only through `fetchOrders()`.
- Fix: delete the try/catch. The ternary is enough, since `promisedAt` may legitimately be null.

### 4. `status ?? "unknown"` and the `fallbackLabel` option are unnecessary (necessity; traced)
- Where: badge.js:10-12 and the `options` parameter.
- What happens: the contract requires `status` and restricts it to the five values (order.schema.json:4-6). `fetchOrders` rejects anything else with `ContractError`. The "Unknown" fallback and the caller-supplied `options.fallbackLabel` are unreachable by supported callers. Nothing in the repo passes `options` except the test written for it. The two tests at test/badge.test.js:15-21 pin behavior the contract excludes.
- Fix: remove the fallback, the option and those two tests. If an out-of-contract status should be surfaced, let it fail loudly rather than inventing a label.

### 5. Status-label table duplicated (design; judgment)
- Where: badge.js:1-7 duplicates `STATUS_LABELS` in src/orders/labels.js:1-7.
- What happens: adding or renaming a status now needs two edits, and the old table is still used by export.js. This duplication is how the screen and the export diverged (finding 1).
- Fix: have `badgeLabel` use `statusLabel` from labels.js, or put the delay rule in labels.js so there is one label function for both consumers.

### 6. Tests miss the required behavior (tests; traced)
- Where: test/badge.test.js, test/list.test.js.
- What happens: there is no test for the promised-date boundary (same day stays "Shipped", next day is "Delayed"). A same-day test would have failed and caught finding 2. There is no test for a null `promisedAt` on a shipped order, which the contract allows for in-store pickup and which should stay "Shipped". There is no export test, so finding 1 passes. The existing "Delayed" test uses a promise 19 days in the past, which any comparison direction would satisfy.
- Fix: add shipped cases for promised == today, yesterday and null. Add a `toCsv` test that a late shipped order says "Delayed". Drop the two fallback tests (finding 4).

## Questions and oddities
- `renderList` gained a `now` parameter that `toCsv` has no equivalent for. Which timezone should "today" be in for the screen and the export? Product input or a project convention would settle it.
- The module is called `badge.js` and the function `badgeLabel`, but the task speaks of labels and `labels.js` already exists. If there is a "badge" concept elsewhere, it is not in this repo.
