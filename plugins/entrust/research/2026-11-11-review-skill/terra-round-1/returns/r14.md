1. **[P1] Повторная выдача задания нарушает гарантию для подтверждённого сообщения.** Проверка в [deliver.js](case/head/src/delivery/deliver.js:8) использует `Set` из [store.js](case/head/src/delivery/store.js:1), который теряется при завершении процесса. Именно после его гибели очередь может выдать задание снова. Если endpoint уже вернул `200`, новый процесс отправит сообщение повторно. Нужны сохраняемое состояние и явное решение для сбоя между получением ответа и сохранением подтверждения; один ключ идемпотентности не доказывает, что повторной отправки не будет.

2. **[P1] Ограничение в три попытки действует только внутри одного вызова.** Счётчик в [deliver.js](case/head/src/delivery/deliver.js:11) начинается с единицы при каждой повторной выдаче задания. Если процесс погибнет после двух временных ответов, следующий обработчик сможет выполнить ещё три запроса. Количество попыток необходимо сохранять между выдачами задания. Тест проверяет только один вызов `deliver`.

3. **[P1] Постоянный отказ ошибочно записывается как подтверждение.** Условие в [deliver.js](case/head/src/delivery/deliver.js:17) включает `permanent`. После ответа `400` вызов `redeliver` для исправленного endpoint пропустит отправку и сообщит `delivered`, хотя сообщение не было принято. Отмечать подтверждение следует только для `ok`; нужен тест повторной доставки после отказа.

4. **[P2] После последней попытки выполняется лишняя задержка.** В [deliver.js](case/head/src/delivery/deliver.js:14) третий временный ответ вызывает ожидание в 8 секунд, хотя следующей попытки уже не будет. Это задерживает возврат результата и оставляет дополнительное окно для гибели обработчика. Тесту стоит проверять число и значения задержек: между тремя попытками их должно быть две.
