## Verdict

The change does not yet meet the task: a shipped order becomes delayed during its promised date, and CSV export still uses the original status label. The new helper also duplicates the existing labels and handles statuses that the contract rejects.

## Findings

### 1. Orders become delayed on the promised date (behavior; traced)

- **Where:** `src/orders/badge.js:21` — `promised < now`
- **What happens:** For a shipped order promised on `2026-03-20`, at `2026-03-20T09:00:00Z` the parsed date is midnight UTC, so the screen shows “Delayed” on the promised date itself.
- **Evidence:** The contract defines `promisedAt` as a calendar date at `contracts/order.schema.json:8-11`; the list calls this helper at `src/orders/list.js:3-4`.
- **Fix:** Compare calendar dates so the promised date remains “Shipped” throughout that date.

### 2. CSV export never uses the delayed label (behavior; traced)

- **Where:** `src/orders/export.js:4` — `statusLabel(order.status)`
- **What happens:** An overdue shipped order appears as “Delayed” on the screen but “Shipped” in CSV.
- **Evidence:** `src/orders/list.js:4` uses `badgeLabel`, while `src/orders/export.js:1-4` still uses `statusLabel`, whose shipped label is defined at `src/orders/labels.js:4`.
- **Fix:** Use the same date-aware labeling rule in both paths.
