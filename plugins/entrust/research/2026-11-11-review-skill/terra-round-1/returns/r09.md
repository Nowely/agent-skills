## Verdict

Изменение не полностью выполняет задачу: порог лояльности задан неверно, а без купона скидка меняет исходную корзину и влияет на решение о бесплатной доставке. Кэш также сохраняет устаревший статус клиента.

## Findings

### 1. Корзина изменяется при расчёте, и скидка накапливается (behavior; traced)

- **Where:** `src/checkout/total.js:15` — `item.price = round2(item.price * 0.95);`
- **What happens:** Для лояльного клиента без купона расчёт перезаписывает цены товаров. При повторном расчёте той же корзины скидка применяется ещё раз: цена 100 превращается сначала в 95, затем в 90,25. В сводке показывается уже изменённая цена.
- **Evidence:** `src/checkout/summary.js:3-7` повторно вызывает расчёт с тем же объектом корзины и выводит `item.price`. До изменения расчёт цены корзину не менял.
- **Fix:** Не менять `item.price`; вычислять скидку на отдельной величине после расчёта исходного subtotal.

### 2. Бесплатная доставка определяется после скидки лояльности (behavior; traced)

- **Where:** `src/checkout/total.js:18` — `subtotal += item.price * item.quantity;`
- **What happens:** Лояльный клиент без купона с исходным subtotal 50 получает subtotal 47,50 и платит 4,90 за доставку. По задаче доставка должна оставаться бесплатной.
- **Evidence:** Цена уже уменьшена в `src/checkout/total.js:14-15`, а `src/checkout/total.js:32` сравнивает получившийся subtotal с порогом 50. `brief.md` требует принимать решение по subtotal до скидок.
- **Fix:** Рассчитывать subtotal из исходных цен и использовать его для доставки и возвращаемого subtotal.

### 3. Клиент с пятью заказами не получает скидку (behavior; traced)

- **Where:** `src/checkout/loyalty.js:6` — `customer.completedOrders > LOYALTY_MIN_ORDERS`
- **What happens:** При ровно пяти завершённых заказах условие ложно, хотя скидка положена.
- **Evidence:** Константа равна 5 (`src/checkout/loyalty.js:1`); `brief.md` задаёт пять **или более** заказов.
- **Fix:** Использовать сравнение `>=`.

### 4. Кэш оставляет устаревшие права на скидку (behavior; traced)

- **Where:** `src/checkout/loyalty.js:5` — `if (loyaltyCache.has(customer.id)) return loyaltyCache.get(customer.id);`
- **What happens:** После первого расчёта изменение числа заказов или статуса сотрудника для того же ID игнорируется. Например, клиент, признанный лояльным, продолжит получать скидку и после того, как переданный `customer.isStaff` станет `true`; затем к ней добавится скидка сотрудника.
- **Evidence:** Кэш ключуется только по ID (`src/checkout/loyalty.js:2, 5-7`), а скидка сотрудника применяется независимо (`src/checkout/total.js:29`). Механизма обновления кэша нет.
- **Fix:** Вычислять условие по переданному объекту при каждом вызове и удалить кэш.

### 5. Скидка без купона округляется на каждом товаре (behavior; traced)

- **Where:** `src/checkout/total.js:15` — `round2(item.price * 0.95)`
- **What happens:** Скидка считается и округляется на единицу товара, а не на subtotal. Например, для десяти товаров по 0,05 округлённая цена единицы остаётся 0,05, поэтому скидка фактически не применяется.
- **Evidence:** `src/checkout/total.js:15-18` округляет цену до умножения на количество; ветка с купоном применяет множитель к общей сумме (`src/checkout/total.js:22-25`). Задача задаёт скидку на subtotal.
- **Fix:** Применять множитель к общей сумме после купона, сохранив существующее округление налога и итога.

### 6. Добавлен обход скидки, которого задача не требует (necessity; traced)

- **Where:** `src/checkout/total.js:9, 12` — `options = {}` и `!options.skipLoyalty`
- **What happens:** Новый параметр позволяет отключить скидку для подходящего клиента, хотя задача предусматривает её предоставление. В репозитории нет вызывающего кода, которому нужен этот режим.
- **Evidence:** Единственный производственный вызов — `src/checkout/summary.js:5`; все вызовы в `test/total.test.js` также передают два аргумента.
- **Fix:** Удалить параметр и проверку `skipLoyalty`.

### 7. Тесты пропускают ключевые регрессии (tests; traced)

- **Where:** `test/total.test.js:21-27` — тесты лояльного клиента и сотрудника.
- **What happens:** Они проходят при неверной границе в пять заказов, устаревшем кэше, повторном изменении корзины и неверной доставке на пороге. Нет проверки совместного применения купона и скидки лояльности. Тест лояльности закрепляет изменённый subtotal 95 вместо исходного 100.
- **Evidence:** Все новые примеры используют уникальные ID, 12 заказов и корзину на 100; тест доставки с купоном использует нелояльного клиента (`test/total.test.js:12-14`).
- **Fix:** Проверить границу 4/5 заказов, повторный расчёт одной корзины, изменение данных клиента с тем же ID, доставку при исходном subtotal 50 и скидку после купона; ожидать исходный subtotal.

## Questions and oddities

Нет.

## Coverage

1. **Скидка 5% при пяти и более заказах — частично:** `src/checkout/loyalty.js:6`, `src/checkout/total.js:14-26`; граница и расчёт без купона неверны.
2. **Скидка после купона — частично:** порядок присутствует в `src/checkout/total.js:22-25`, но теста совместного применения нет.
3. **Сотрудники не получают скидку лояльности — частично:** проверка есть в `src/checkout/loyalty.js:6`, но её может обойти устаревшее значение кэша.
4. **Налог и доставка без изменения правил — частично:** формула налога сохранена (`src/checkout/total.js:33`), но исходная сумма без купона меняется; решение о доставке нарушено (`src/checkout/total.js:32`).

Прочитаны изменённые файлы целиком и их базовые версии, вызывающий код `summary.js`, `money.js`, `package.json` и все найденные ссылки на изменённые функции. Код и тесты не запускались по ограничению ревью; запуск тестов подтвердил бы их фактический результат.
