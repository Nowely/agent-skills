## Verdict

The change retries temporary responses within one invocation, but it does not enforce the three-attempt limit across queue redelivery or prevent resending an acknowledged message after a worker dies. It also records permanent failures as acknowledgements, breaking the existing operator redelivery path.

## Findings

### 1. Attempt limit resets when the queue redelivers a job (behavior; traced)

- **Where:** `src/delivery/deliver.js:11` — `for (let attempt = 1; attempt <= MAX_ATTEMPTS; attempt++) {`
- **What happens:** If a worker sends one or more temporary attempts and dies before returning, the queue can hand the job to another worker. Its loop starts at attempt 1 again, allowing more than three total sends.
- **Evidence:** `src/queue/worker.js:3-6` describes redelivery after process death; `src/delivery/deliver.js:10-15` keeps the count only in a local variable.
- **Fix:** Persist the attempt count across worker processes and reserve each attempt before sending. Test a redelivery after an interrupted attempt.

### 2. An acknowledged message can be sent again after worker death (behavior; traced)

- **Where:** `src/delivery/deliver.js:8` — `if (wasAcknowledged(message.id)) return { kind: "ok", skipped: true };`
- **What happens:** The acknowledgement check reads a process-local set. If a worker receives an `ok`, records it, and dies before returning, a replacement process starts with an empty set and sends the message again.
- **Evidence:** `src/delivery/store.js:1-8` stores acknowledgements in an in-memory `Set`; the queue’s process-death redelivery is documented at `src/queue/worker.js:3-4`. The existing test at `test/deliver.test.js:17-23` calls `deliver` twice in the same process.
- **Fix:** Use acknowledgement state that survives process death. Also establish a protocol for the crash window between the endpoint accepting a request and that state being recorded: durable local state alone cannot prove that an already accepted request was not sent again.

### 3. Permanent rejection is recorded as successful acknowledgement (behavior; traced)

- **Where:** `src/delivery/deliver.js:17` — `if (result.kind !== "temporary") markAcknowledged(message.id);`
- **What happens:** A `400` is marked acknowledged. When an operator later invokes `redeliver` after the endpoint is fixed, `deliver` skips the send and the command reports `"delivered"` despite the endpoint never accepting it.
- **Evidence:** `src/delivery/send.js:6-8` distinguishes `ok` from `permanent`; `src/admin/redeliver.js:4-7` explicitly supports retrying a rejected message. The base implementation marked only `ok`.
- **Fix:** Mark acknowledgement only for `result.kind === "ok"`; add a test covering permanent rejection followed by operator redelivery.

### 4. The final temporary response incurs a delay with no next attempt (behavior; traced)

- **Where:** `src/delivery/deliver.js:14` — `await sleep(backoffMs(attempt));`
- **What happens:** After the third temporary response, delivery waits another 8 seconds before returning, although there is no fourth attempt. A process death during that unnecessary wait also exposes the job to redelivery.
- **Evidence:** The loop ends after attempt 3 at `src/delivery/deliver.js:11-15`; `src/delivery/backoff.js:1-4` maps attempt 3 to 8,000 ms. The test’s no-op sleep at `test/deliver.test.js:9` does not check the waits.
- **Fix:** Sleep only when another attempt remains, and assert the two expected delays for three temporary responses.

## Questions and oddities

None.

## Coverage

1. **At most three attempts per message — partial:** capped within one invocation at `src/delivery/deliver.js:11`, but the counter does not survive queue redelivery.
2. **Retry only temporary; stop on ok or permanent — done within one invocation:** `src/delivery/deliver.js:12-13`; permanent outcomes are nevertheless recorded incorrectly.
3. **Existing backoff between attempts — partial:** `src/delivery/deliver.js:14` uses `backoffMs`, but also waits after the final attempt.
4. **Never resend an acknowledged message, including queue redelivery — partial:** `src/delivery/deliver.js:8,17` handles repeated calls in one process, not process death.
