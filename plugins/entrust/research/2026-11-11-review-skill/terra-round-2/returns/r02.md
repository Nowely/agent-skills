- **[P2] Empty CSV records are silently dropped** — [import.js:31](case/clean/src/contacts/import.js:31). The existing parser discards records whose cells are all empty, so `name,email\n,\n` produces no rejection. The importer must report that row’s empty name and line number. Add an import test for an all-empty record.

- **[P2] Malformed quoting can still result in writes** — [import.js:31](case/clean/src/contacts/import.js:31). The existing parser accepts quotes in the middle of an unquoted field and characters after a closing quote. For example, `name,email\nAnn"X",ann@site.test\n` is accepted and creates `AnnX`, although the CSV is malformed. This defeats the requirement to write nothing when parsing fails. Cover malformed quoting beyond an unclosed quote.

- **[P2] A `line` column overrides the actual line number** — [import.js:16](case/clean/src/contacts/import.js:16). The parser spreads CSV columns over its own `line` property. With `name,email,line\n,bad,999\n`, the rejection reports `"999"` instead of line 2. Keep record location separate from user-supplied columns and test an extra `line` column.

- **[P2] Rejection lines are wrong after quoted CR line breaks** — [import.js:31](case/clean/src/contacts/import.js:31). The parser supports CR as a record separator but increments its line counter only for LF inside quoted fields. A quoted name containing a CR therefore causes subsequent rejections to report an earlier line. Add a test with CR-separated records and a quoted CR.

The parser issues predate this commit, but the new import exposes them against its requirements. Review was static; project code and tests were not run.
