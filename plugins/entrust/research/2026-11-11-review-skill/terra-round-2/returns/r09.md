- **[P1] Parse the whole file before writing.** [import.js:13](case/head/src/contacts/import.js:13) processes and writes each line immediately and never checks whether a quote was closed. A valid first row followed by an unclosed quoted field leaves the first contact stored, even though the file cannot be parsed. The existing `parseCsv` reports unclosed quotes and can be called before any store mutations.

- **[P1] Preserve quoted line breaks.** [import.js:13](case/head/src/contacts/import.js:13) splits a CSV record at every newline. For example, `"Ann\nSmith",ann@site.test` is treated as two rows, losing the contact and producing incorrect rejection line numbers. The existing CSV parser supports multiline fields and records their starting line.

- **[P1] Count each email only once per file.** [import.js:76](case/head/src/contacts/import.js:76) applies every occurrence independently. For a new address appearing twice, the result reports one creation and one update; for an existing address, it reports two updates. Deduplicate normalized emails before writing and counting, retaining the last valid row.

- **[P1] Use the address book’s email validation.** [import.js:1](case/head/src/contacts/import.js:1) accepts values such as `ann@site` and `a@b@c`, although the existing `isEmail` rejects them. These rows are created instead of being reported as rejected.

- **[P1] Do not silently discard a domain.** [import.js:72](case/head/src/contacts/import.js:72) skips every `@example.invalid` address, including addresses accepted by the existing validator. Such rows are neither imported nor reported as rejected; the task specifies no domain exception.

- **[P2] Propagate insert failures.** [import.js:85](case/head/src/contacts/import.js:85) retries every exception and then silently skips the contact. A store failure therefore returns a seemingly successful result with missing contacts and no explanation.

- **[P2] Continue after rejected rows in every mode.** [import.js:59](case/head/src/contacts/import.js:59) introduces a strict mode that throws on invalid data, contrary to the requirement that rejected rows not stop the import. Earlier rows may already have been written when it throws.

The tests do not cover parse failure atomicity, multiline records, duplicate counts, invalid addresses, or store failures; one test instead asserts the unsupported domain skip. This was a static review; tests were not run.
