- **[P1] Повторная отправка при параллельных запусках** — [overdue.js:9](case/clean/src/invoices/overdue.js:9). Два вызова `runNightly` могут одновременно увидеть счёт без отметки и оба вызвать `mailer.send`: отметка записывается только после завершения отправки. Это нарушает требование уведомлять один раз. Тесты проверяют только последовательные запуски.

- **[P2] Уведомление об уже оплаченном счёте** — [overdue.js:8](case/clean/src/invoices/overdue.js:8). `repo.unpaid()` формирует список до первой асинхронной отправки. Пока она ожидается, другой счёт из этого списка может быть оплачен; цикл всё равно отправит по нему уведомление, поскольку повторно `paidAt` не проверяет. Нужна проверка актуального состояния перед отправкой и тест с оплатой во время ожидания предыдущего письма.
