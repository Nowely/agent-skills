- **[P1] Every successful invoice is emailed again on subsequent nights.** [overdue.js](case/head/src/invoices/overdue.js:2) selects every unpaid overdue invoice each time, and nothing records a successful notification. Persist a notification marker only after `mailer.send` succeeds; leave it unset on failure so that invoice is retried.

- **[P1] The email never contains the required invoice details.** [templates.js](case/head/src/notifications/templates.js:2) registers `invoice_overdue`, but the emitted event and lookup use `invoice.overdue`. Every send therefore uses the generic fallback, which omits the number, amount and due date.

- **[P2] Invoices are notified on their due date.** [overdue.js](case/head/src/invoices/overdue.js:3) uses `<= today`, although the due date must have *passed*. Compare with `< today` for the specified UTC calendar dates.

- **The new notification framework is disproportionate to the requested behavior.** [nightly.js](case/head/src/jobs/nightly.js:14) introduces an event bus, channel registry, configuration, template engine and channel hierarchy for one email. A direct overdue-invoice step using the existing mailer and amount formatter would remove indirection and the template-key mismatch.

The added tests exercise framework components but never run `runNightly` with an overdue invoice or inspect the message content. Add coverage for the due-date boundary, successful sends across two nights, and a failed send followed by another invoice and a retry the next night. This was a static review; code and tests were not run.
