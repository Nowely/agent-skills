## Change

The nightly job emails customers about overdue unpaid invoices, records successful sends, and retries failed sends.

Requirements from `brief.md`:

1. Notify only unpaid invoices whose due date has passed, using UTC calendar dates.
2. Include the invoice number, amount and due date.
3. Notify each invoice once.
4. Continue after a failed send and retry that invoice the next night.

Sources: `brief.md`, the last commit and its diff.

## Verdict

The normal sequential path meets the requirements, including retry after a rejected send. Overlapping runs can send duplicate emails, and an invoice paid while the job is waiting on an earlier send can still be notified.

Target: keep the existing nightly step, amount formatter and mailer; coordinate notification attempts so an invoice has only one in flight, and check that it is still unpaid immediately before sending. Keep the successful-send marker and retry behavior.

Recommendation: fix the two concurrency findings in place, then add regression tests for them and for future due dates.

## Findings

### 1. Overlapping runs can notify the same invoice twice (behavior; traced)

`src/invoices/overdue.js:9`: Two calls to `runNightly` sharing a repo can both reach an unmarked invoice before either awaited `mailer.send` completes. Both send the email, then both mark it. This breaks requirement 3.

Fix: coordinate attempts for the same invoice so a second run cannot send while the first is in flight, while leaving a failed attempt retryable. Add a test with two overlapping runs and a deferred send.

### 2. An invoice paid during the job can still be emailed (behavior; traced)

`src/invoices/overdue.js:8`: `repo.unpaid()` creates an array once. If the first send waits, and `repo.update` marks a later invoice paid before that send completes, the later invoice remains in the array and is sent without another paid check. This breaks requirement 1.

Fix: check the current payment state immediately before each send. Add a test that pays the second invoice while the first send is pending.

### 3. Future due dates are not covered by a test (tests; traced)

`test/nightly.test.js:19`: The test covers a due date equal to today and one in the past, but not a future date. Changing `invoice.dueDate >= today` to `invoice.dueDate === today` would pass these tests and notify an invoice before it is overdue, breaking requirement 1.

Fix: include an unpaid invoice due after today and assert that no email is sent for it.
