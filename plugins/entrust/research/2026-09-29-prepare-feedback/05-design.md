# field-report: проект навыка (Fable F1, итерация 02)

2026-09-29. Правка итерации 01 по разбору Opus O1 (`O1-critique-01.md`, 17 находок), проверке 20 утверждений агентами Luna (15 confirmed, 5 overstated) и наблюдению координатора о Skill tool. Мерило правки — предпочтения владельца: самое простое, что воспроизводит пять эталонов; никаких защит от гипотетических рисков; правило без оговорок; платные прогоны только по его слову. Файл 01 не тронут; здесь — весь проект заново, короче там, где ничего не изменилось. Новые и изменённые утверждения — в `F1-claims-02.md`.

## 1. Имя и место

Без изменений: `field-report`, `/entrust:field-report`, место — entrust (все пять эталонов стояли на лаунчере, swarm, каталоге состояния и ролях orchestrate; у terse нет Codex-пути). Одна строка в README terse.

**Форма страницы.** `disable-model-invocation: true`. Первая строка: прочитать `${CLAUDE_SKILL_DIR}/../orchestrate/SKILL.md` целиком инструментом Read, как foreman.md велит foreman'у; в прочитанном тексте `${CLAUDE_SKILL_DIR}` означает каталог orchestrate, а `${CLAUDE_PLUGIN_DATA}` страница даёт явно (подставляется только в теле навыка). Дальше действует orchestrate: карточка плана, композиция, капы, обёртка и опрос, одобрения, пять полей, runner, линтер, критик с манифестом; codex загружается Skill tool, когда в плане есть Codex-агент. Страница field-report держит только то, что меняет: меню фокусов (§2), корпус (§3), два способа чтения (§4), отчёт как публикацию (§5), приватную папку и рецензента (§6). Детали — `references/focuses.md` (по разделу на фокус: единица, метки, раскладка, способ чтения) и один скрипт `scripts/field-report.mjs`.

## 2. Запуск и меню фокусов

`/entrust:field-report [слова]`. Первые две строки: где запущен и куда пойдёт результат; какие плагины найдены в сессиях. Меню:

| Фокус | Вопрос | Единица | Способ чтения | Эталон |
|---|---|---|---|---|
| `version` | как плагин вёл себя в версии или окне версий | находка о поведении плагина; линза «полезность ролей» — запуск агента с метками used / decisive / miss / harm / unknown | читатели по вопросу | #15, #16 |
| `run` | один прогон: сбой, ограничение или замеры | событие или замер одной сессии и её запусков | читатели по вопросу | #1, #22 |
| `feedback` | как пользователь реагировал на тему | эпизод: реплика пользователя × черновик | исчерпывающее извлечение | #20 |
| своими словами | что угодно | координатор пишет единицу, закрытые метки и раскладку в плане | по единице: закрытый набор по многим сессиям — извлечение, иначе читатели | — |

Фокус задаёт четыре вещи: единицу, закрытые метки, раскладку выхода (§5) и способ чтения (§4). Сверки с issues и `ISSUES.md` нет (требование 6).

## 3. Отбор сессий и область

**Сигнал загрузки** — `Base directory for this skill: <любой путь>/<plugin>/…/skills/<skill>` в транскрипте (`~/.claude/projects/<slug>/<session>.jsonl`): на этой машине 38 сессий entrust и 10 terse; из них 26 и 8 из кеша плагина, остальные — из checkout'ов в worktree. Версия — из пути кеша; для checkout — из манифеста плагина по этому пути, если он ещё есть, иначе `unknown`. Отказ загрузки — текст `cannot be used with Skill tool due to disable-model-invocation` в `tool_result` (16 сессий на машине): для `version` это находка, не сигнал отбора. Рядом: субагенты в `<session-id>/subagents/agent-*.jsonl`; отчёты Codex — по строке `REPORT=` из транскрипта, не по договорённости о каталогах (38 транскриптов несут её; корни — `entrust-nowely/orchestrate/…`, `entrust-nowely/reports/…`, `codex-delegate-nowely/…`); отчёт, которого по пути уже нет, — `unknown`; rollout-логи Codex — по `threadId` отчёта.

**Скрипт** `field-report.mjs corpus`: обходит транскрипты, отбирает по фокусу и словам, исключает текущую сессию, склеивает форки (одинаковые ходы и метки времени — одна сессия), считает сообщения, символы, токены по `usage`, субагентов и запуски; для извлечения режет на части ~60k символов с перекрытием и страницы ≤ 18k (#21 сообщает эти размеры; #22 п. 4); пишет индекс в приватную папку (§6), печатает сводку через runner. Сессии с маркером `/entrust:field-report` — отдельной строкой плана, исключены по умолчанию.

**Область по фокусу:** `version` — все проекты, версии из слов; `run` — сессия по дате или id и её запуски; `feedback` — сессии с загрузкой плагина, и второй строкой в плане «все сессии с человеческими сообщениями: N» (первый прогон #20 — это она). План перечисляет проекты по `cwd` как область; исключения — обычные слова. Предупреждение, если старые сессии удалены (хранение 30 дней по умолчанию — #21) или корпус мал. Остановка; «go» покрывает показанное.

## 4. Два способа чтения

Способ задаёт фокус; размер корпуса масштабирует внутри способа. Ряды — из таблицы orchestrate, состав — по правилам композиции codex и словам пользователя о том, что доступно («сейчас только Luna»). Все агенты чтения — read-агенты.

**Читатели по вопросу** (`version`, `run`). Один сильный читатель на задачу или сессию (форки — одна задача), с вопросом и адресами в возврате; foreman при трёх и больше; критик разбиения перед любым фан-аутом шире одного агента (orchestrate:127); замерщик-скрипт там, где есть числа (токены по `usage`, таймауты и `Wall time` из отчётов и rollout-логов — #1; токены по ролям, покрытие, тайминги пустых чтений — #22); для entrust — аудитор Codex-запусков по отчётам; для `version` — dry run страниц (сильный читатель проходит шаги страницы, не запуская их; описан в `focuses.md` как роль по правилу roles.md) и два blind proposer'а для таблицы предложений (#15); dedup-and-rank при нескольких читателях; один опровергатель на кластер; черновик по раскладке эталона; один свежий сильный читатель с обоими брифами — полнота и публикация с комбинациями. Судьи нет: ранжирует координатор, как в #15. Платный повтор (контроль #1) — строка плана с ценой, по слову.

**Исчерпывающее извлечение** (`feedback`; любой фокус с закрытым набором по многим сессиям). Корпус keep/drop и части (§3) → критик разбиения на бриф и метки → пилот против эталона по протоколу, записанному до пилота (сильный ряд размечает 2–3 единицы; bulk-модель на двух усилиях; ворота и порядок — recall, лишние, токены; эффорт извлечения — тот, что выбрал пилот: в первом прогоне medium, в реплике high) → пересчёт по частям, план снова, остановка → извлечение батчами `swarm.mjs` по странице swarm (≤ 50 единиц на файл, каждому батчу свой каталог прогона, иначе `PATH=taken`; единица батча — часть, `{{UNIT}}` — её путь; редуктор считает возвраты, которые не разобрались или вышли не нулём) → покрытие по rollout-логам (`field-report.mjs coverage`: страница прочитана, если её текст целиком есть в одном выводе команды треда) и перезапуск непрочитанного → слияние (сильный) и точные цитаты (`field-report.mjs quotes`) → два независимых анализа → черновик (верхний ряд) → stress-тест swarm'ом (единица — принцип × эпизод, по определению единицы swarm) и контрпримеры по частям → судья (верхний) → сравнение с прошлым прогоном, если он есть → критик полноты и рецензент публикации, два агента, как держала реплика.

**Остановка по стоимости** — на границе батча: `field-report.mjs tokens` суммирует `tokenUsage` отчётов батча и сравнивает с медианой пилота; больше 3× у одного агента или прогноз выше плана в 2× — стоп и вопрос; идущий батч доходит до конца. Замеры — файлами в приватной папке. Правила bulk-ряда из #22 (эффорт, параллельность, батч-режим) здесь не переписаны: им место в orchestrate и swarm отдельными строками changelog, и field-report ссылается на страницы, какие они есть.

## 5. Выход

**Место решает:** корень `git rev-parse --show-toplevel` с `.claude-plugin/marketplace.json`, `"name": "nowely"` — внутри (worktree тоже); иначе снаружи.

**Отчёт — публикация, не ответ.** Тело — файл в приватной папке; критик полноты читает его по манифесту (roles.md:26: публикация читается так же); линтер проходит только короткий ответ. После строки критика выводится заголовок и тело одним Markdown-блоком — это и есть публикация, названная в манифесте; навык ничего не публикует.

**Снаружи:** заголовок и блок. **Внутри:** `plugins/<name>/research/<date>-<slug>/` с тем же отчётом серией черновиков `01-report.md`, `02-report.md`… по CLAUDE.md, `rounds.md` по раундам критиков, замеры, на которые отчёт ссылается, строка в `plugins/<name>/research/README.md`; возвраты шагов остаются в приватной папке; `anonymized/` — только если отчёт на него ссылается. Строка плана говорит, куда лягут файлы: живое дерево без коммита или worktree; решает пользователь словами. `<name>` — плагин, о котором отчёт.

**Формат** — раскладка эталона фокуса, в `focuses.md`: `version` — #15 (Summary, Scope and method, Cost profile, находки F с полями Seen / Pages / Kind / Level / Refuter / Recurring против `CHANGELOG.md` плагина, What to keep, Proposed changes, Open questions, cost; линза ролей — #16); `run` — #1, если находка одна (Setup, What happened, аргумент, P0…Pn, What worked, Versions), #22, если список замеров (пары measured → proposed, таблица цен); `feedback` — #20 (принцип «когда … — делай …, потому что …», сила по независимым диалогам, граница, before/after с пометкой подтверждения, Method, Limitations). Заголовок — по образцу эталона: `<plugin> <version> field report: <выводы>`; `Field report: <что случилось> — <тезис>`; `<тема>: N principles from M feedback episodes`; `<прогон>: measured fixes for <что>`. Адреса — `T#:line`, `sub:`, `run:` (нотация #15); карта `T#` — в приватной папке.

## 6. Приватность

Принцип CLAUDE.md:24–26 и комментария к #21, без списка: наружу уходит только то, что владелец опубликовал бы на главной странице репозитория, и деталь, приватная в сочетании с публичным, — приватная. Механика:

1. **Приватная папка** `<state>/field-report/<date>-<slug>/` под `${CLAUDE_PLUGIN_DATA}`, по образцу `experiments/` навыка experiment; пишет её один скрипт: `corpus` — индекс, части и страницы; `add` — книгу единиц с картой `T#`, замеры, черновики отчёта. Отчёты Codex остаются у драйвера, брифы и возвраты — где их оставил orchestrate.
2. **Транскрипты читают агенты**, координатор — возвраты и сводки.
3. **Рецензент публикации** — сильная модель, которая текст не писала: проверяет каждую деталь выходящего файла — строки ошибок, имена инструментов, типы монтирования, «форму» задач, даты, счёты — по двум вопросам: опубликовал бы это владелец на главной странице, и склеивается ли это с уже публичным (прошлые issues, README research-папок; без GitHub — с самим отчётом). Список снятого и утверждений, чью опору раскрыть нельзя, идёт пользователю с текстом.
4. Внутри репозитория та же проверка перед записью каждого файла в `research/`.
