# Ревью

- **P1 — CSV не проверяется целиком до записи** ([import.js:13](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L13), [import.js:76](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L76)). Самодельный разбор не обнаруживает незакрытые кавычки и кавычки внутри поля: файл с корректной первой строкой и последующей некорректной строкой уже изменит хранилище, хотя при ошибке разбора не должно быть записано ничего. Он также разбивает поля с переводом строки на отдельные записи и неверно определяет номера последующих строк. В проекте уже есть `parseCsv`, который обрабатывает эти случаи и сообщает ошибки; его результат нужно получить до изменений хранилища.
- **P1 — Неверное определение адреса** ([import.js:1](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L1), [import.js:65](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L65)). Регулярное выражение принимает, например, `ann@site` и `a@b@c`, хотя существующая `isEmail` их отклоняет. Такие строки создают или изменяют контакты вместо отказа. Нужна общая валидация адресной книги.
- **P1 — Валидные адреса молча пропускаются** ([import.js:72](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L72)). `Ann,ann@example.invalid` проходит существующую валидацию, но не создаёт контакт и не попадает в отказы. Исключение домена не предусмотрено задачей; тест закрепляет неверное поведение.
- **P2 — Дубликаты считаются несколько раз** ([import.js:76](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L76)). Для двух валидных строк нового `a@site.test` возвращается `created: 1, updated: 1`, а для существующего контакта — `updated: 2`. По условию адрес в файле считается один раз; необходимо сначала выбрать последнюю валидную строку для нормализованного адреса и затем применить её. Невалидный дубликат не должен вытеснять предыдущий валидный.
- **P2 — Строка из пробелов теряется** ([import.js:21](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L21)). `name,email\n   \n` должна дать отказ для строки 2 с пустым именем, но `trim()` делает её неотличимой от физически пустой строки.
- **P2 — Ошибки сохранения скрываются** ([import.js:83](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L83)). Любая ошибка `insert` трижды подавляется, после чего строка исчезает из результата без создания и без отказа. Например, при недоступном хранилище вызывающий получит видимость успешного импорта. Повторные попытки и молчаливый пропуск не требуются задачей; ошибку записи следует сообщить вызывающему.
- **P2 — Strict mode прерывает обработку отказанной строки** ([import.js:58](https://github.com/Nowely/agent-skills/blob/843c2a392d31a7bb2129b61d7d74f226fafbb9c7/plugins/entrust/evals/review/cases/contact-import-v2/head/src/contacts/import.js#L58)). При `{ mode: "strict" }` пустое имя или неверный email вызывает исключение, и последующие допустимые строки не импортируются, вопреки условию о продолжении импорта. Если до ошибки были допустимые строки, они уже сохранены. Режим и соответствующий тест вводят не запрошенное поведение.

Тесты проверяют только простой путь и дополнительно закрепляют два не требуемых поведения. Нужны проверки результата и содержимого хранилища для ошибок CSV после валидной строки, многострочных полей и физических номеров строк, валидации через `isEmail`, пробельных и неполных строк, нормализованных дубликатов с последней валидной строкой и отказов без остановки импорта. Проверка статическая; тесты не запускались по условиям задания.
