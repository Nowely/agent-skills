## The four themes the owner asked about

**(a) Catalogues of agent roles and role specialisation.** For: Anthropic's decision page names three cases where specialisation pays and ties them to tool-surface signals (20+ tools, domain confusion, degradation on adding tools), not to job titles; Google's ADK rebuild reports that narrow specialists ran more reliably than one long prompt; Cursor's final design is explicitly a role hierarchy (root planner, subplanners, workers) and reports ~1,000 commits/hour over a week. Against: the Magentic-One authors chose tool-based agents over role-based ones and state the reason - role catalogues force redundant capability into several agents - while conceding the comparison is untested; Manus's Wide Research fans out identical general-purpose instances and names predefined roles ("manager", "coder", "designer") as the thing it is not doing; Anthropic reports an experiment where planner/implementer/tester/reviewer agents spent more tokens coordinating than working; Cursor reports that loading one agent with nine objectives produced sleeping, premature-completion and refusal-to-delegate. The split in the evidence is consistent: specialising by tool or by context boundary is defended, specialising by phase of the same work is attacked.

**(b) A persistent counterpart agent over many turns versus one-shot briefs.** The strongest positive instance found is Amp's oracle, and it is not persistent: it is a read-only advisor seat summoned per call, deliberately not pushed by the system prompt because of cost and latency, chosen for a different training lineage and disqualified from the main seat for being "less proactive". Amp frames the pair as "two distinct voices in the same conversation". Against persistence: Cognition states flatly that in 2025 agents cannot hold the long-context proactive discourse that peer collaboration needs; Anthropic's research system runs subagents synchronously and reports that the lead "can't steer subagents"; OpenAI's shipped subagent surface reports activity but offers no control to stop or steer an individual agent; Magentic-One forces every agent to clear its context when the plan is revised, so no continuation survives a re-plan; Claude Code ships its peer-coordination surface (agent teams) experimental and disabled by default. For continuation within one seat rather than across seats: OpenAI Codex advises keeping one chat per coherent unit of work because it "preserves the reasoning trail", while Claude Code advises the opposite reflex - after two corrections on the same issue, clear and restart. No source found reports operating a long-lived advisor thread and measuring it.

**(c) Cheap models in bulk, and when to trust them.** For: Anthropic's headline configuration is a strong lead over cheaper subagents; Amp moved its codebase-search subagent to a cheap fast model and reports ~8 parallel tool calls per iteration against ~2.5, finishing in ~3 turns instead of ~9, "for the same quality"; OpenAI names a cheap tier for "read-heavy scans" that "works well for parallel workers that return distilled results to the main agent"; Magentic-One's authors expect grounding and summarising to move to smaller models. The stated condition in every case is the same: the cheap seat does bounded read-heavy work and returns something distilled. Caution: Amp's own report after swapping its default model is that at the level of one engineer on one task the model choice did not visibly change the result, and that what changes the output is task difficulty, context and review - a claim that cuts against tier-shopping as a management lever.

**(d) Budget or capacity models for a pool of agents of different cost.** The only explicit width-and-effort budget found is Anthropic's, embedded in the orchestrator prompt as rules keyed to query class (1 agent / 3-10 calls, 2-4 subagents / 10-15 calls each, 10+ subagents), introduced after an uncapped orchestrator spawned 50 subagents for a simple query; Anthropic also states the admission price in token multiples (15x chat for multi-agent; 3-10x single-agent for the same task on a later page) and says the system "requires tasks where the value of the task is high enough". Claude Code states a bulk width band of 5 to 30. Cursor reports that a quantity word ("many") produces conservative output and a range ("20-100 tasks") changes behaviour. Magentic-One's stall counter is described as "a limited budget to recover from small errors", and Google's lesson is to bound the retry loop in the harness so a loop cannot "burn through your token budget in minutes". No source found publishes a capacity model that prices a mixed pool - the budgets are per-task effort caps and per-loop circuit breakers, not an allocation across agents of different cost.
