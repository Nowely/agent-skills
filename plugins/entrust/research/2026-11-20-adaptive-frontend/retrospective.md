# Why the work kept coming back

The original task changed an established, selectable configuration card used in more than one screen. The designs covered substantially different layouts, optional data and information shown on demand. The product's content column was narrower than the broadest design. A separate website still composed a card from older public pieces. A local component demonstration, the built package, and the downstream application each answered a different question about delivery.

## Five distinct corrections from the owner

These are a lower bound from the original session. Consecutive messages about the appearance and spacing of one action count as one event. The list does not give five comparable implementation rounds or a clean measure of hours lost.

| What the owner reported | What had been checked or known | An earlier check with a chance of exposing it |
|---|---|---|
| A manufacturer's mark was too small on the narrow card. | The mark was present. The design and the rendered card were later compared at the narrow container width. A second manufacturer did not have an equally authoritative narrow frame. | Measure the visible artwork against the corresponding design state. Resolve the missing specification for the other mark separately from the demonstrated mismatch. |
| The selected card's primary action stretched across the row and touched the bottom border. | The click still worked. A historical public story already represented the selected state and callback. | Select an item through the actual consumer; inspect the action and its bottom spacing before clicking it. A working callback alone says little about the selected layout. |
| A third storage row intersected a long price. Another report showed long core/thread text next to memory, and another showed memory colliding with price. | The available host width and variable-length storage inputs were known. The compact design example and demanding data had been checked separately. | Put competing pieces of valid content into the **same** record at the real host width. Inspect the ink or hit regions of adjacent elements as well as the outer box. |
| A layout repair changed the parent of stateful pricing content. Moving between modes lost state or repeated work. | Width-specific views looked plausible independently. Existing tests already exercised preservation of mounted pricing and hint content. | Keep the selected/open item mounted, change its available space, finish the action and measure the user result. Run the existing focused regression tests when changing parentage. |
| A small informational badge closed on pointer leave, then reopened and drew a focus outline. | Opening a help popup had been checked. The new icon introduced a focusable trigger where the previous label had been plain text. Closing the overlay returned focus to an element that could open it again. | Enter the trigger, move inside the overlay, leave to empty space and wait for the stable state. Interactive content still needs to remain reachable while the pointer is inside. |

There were more differences than those five returns: mobile graphics grouping, missing comparison states for the report, desktop and mobile hint behavior, and feature and naming issues in code review. We have not counted each comment or screenshot as a separate prevented bug. The original requester later approved different product behavior for some cases. A subsequent correct decision is not evidence that the earlier implementer could infer it.

## Where a model could have acted independently

* **Design scope.** The design link represented a group of frames. A single selected node omitted intermediate layouts and interactions. Inspecting the group, the public entry, the adjacent implementation and the data contract was available before changing code. An existing content column measured 624 CSS px while a wide design measured 764. A Storybook container could exercise both widths without changing the host limit.
* **Data and measurement.** A phone-width viewport and a phone-width card are separate inputs. One archived capture named for a 601 px card reported the 1200 px story root in its manifest. That number by itself could not verify the card width. Conversely, a card can have the right width and no horizontal overflow while two strings overlap inside it. An image of one storage line cannot establish that three lines fit.
* **Precedent and intent.** On a subsequent filter task, the earlier implementation agent found a working chip composition within minutes. The new screen placed the rental-period control beside the group instead of in its wrapping flow. Once chips occupied two lines the period centered against both lines. Roughly 44 minutes of calendar time separated the owner's report from a repaired story check. This interval includes communication and is not an estimate of programming effort.
* **Delivery boundary.** The source story can import files that fail to make it into the distributed package. An external consumer may use old public pieces in a composition that current stories never mount. Discover that use while scoping the change. Verify packaged behavior or explicitly record that it is still open.
* **Scope of repair.** A fix to a shared popup or focus mechanism changes other controls. The original work included additional keyboard behavior that was later removed by owner decision. Compare the installed standard control and the existing project abstraction before extending either one. Keep improvements with no requirement outside the change.

## Which uncertainties needed an owner

Initially the owner chose a remaining-quantity threshold for a warning badge, and later replaced it with an explicit data flag. The policy for older public pieces also changed. Removal was allowed at one point; the final decision preserved the external interface and separated deprecated behavior until its consumer could migrate. The final header decision covered ordered items as well. Those are genuine scope or contract decisions. Asking about them is compatible with autonomy.

Other questions were answerable from sources. The original implementation and public fixtures established selection and continuation, the existing network explanation and link, and whether an action was supplied by a particular consumer. If an open design disagrees with an established journey, describe the extra step or lost information and resolve that product choice. A frame that only depicts a closed trigger leaves room to follow the working interaction.

The full trials compressed historical updates into a handoff after initial independent discovery. The worker first identified consumers and questions, then received the actual later decisions before expensive implementation. One worker specifically asked whether to retain explanatory text next to a build price and action. The coordinator initially answered incorrectly. Running the released implementation established that the text and documentation link remained, and the coordinator corrected the answer before submission. This counted as an intervention by the coordinator. The later comparison worker received the correct answer immediately.

## Why crossing projects mattered

Each additional downstream check can entail a development build, publishing an artifact, updating the consuming branch and generated lockfile, rebuilding a stand and rerunning integration checks. Several visually reported defects were reproducible in the library story. This suggests an opportunity to shorten that loop by proving the local case before asking the consumer to rebuild. None of the five studies counted remote builds saved or measured time to a real production merge.

An unauthenticated Storybook is cheap to open in a clean Playwright context. The authenticated stand in the original task needed its configured persistent profile. Launching another browser led to a sign-in detour; a second owner of the same profile could prevent a connection. Keeping public checks independent of that profile gave the implementer useful work while the authenticated check was unavailable. A public demo cannot prove sign-in, real production data or an external transition.

The original session also included manual edits to a generated lockfile after running the package manager, repeated rebases, manual CI dispatch, localization waits and an unrelated typecheck fix that obtained its own review. Those activities help explain the long historical calendar span. They were excluded from the UI timings. A package-promotion skill would require its own experiment and has no demonstrated outcome in this record.
