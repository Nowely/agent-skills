name: adaptive-frontend
description: Implement or change an interactive interface that adapts to available space. Use when matching several design frames, embedding a shared component in different hosts, or preserving a user action as the layout changes.
---

# Deliver one responsive user journey

**Choose the journey.** Open the component through its existing public story or consuming screen. Perform the user's primary action. Identify what the user needs to read, the feedback that indicates selection or progress, and the observable outcome of the action. Record a small baseline you can replay. If the request changes one step, the rest of this journey is the behavior to preserve.

**Read the design as a group.** Compare the same region across the supplied frames. Identify what stays together, what wraps or moves, which information becomes implicit, and where an action remains reachable. Check the actual containing element in the host and in the story. Record both its measured CSS width and the viewport. Follow the code that controls available space before choosing a breakpoint. A screenshot filename or a viewport preset cannot establish the component width.

**Resolve product questions at the cheapest source.** A frame specifies the depicted state. Use the input contract to learn what else can occur and the existing consumer to learn what actions mean. Reuse the closest live component or design-system primitive after checking the installed version. If those sources leave two materially different user outcomes, ask the owner one specific question with the consequence of each answer. Keep independent work moving. Treat a missing mockup for an existing action as a reason to exercise it in the old UI.

**Build through the real entry point.** Choose a representative record for direct design comparison. Then select another valid record where the regions that share space compete for it. Derive it from actual input shape and consumer examples. Render the public component with normal state, handlers, styles and theme. Start with the smallest change that delivers the whole journey. A story may supply data and a resizable host. Presentation belongs in the component that users receive.

**Close the browser loop.**

1. For a public local story, use a clean Playwright context. For a host requiring sign-in, use its configured persistent Playwright profile. Give that profile one owner at a time. If occupied, continue the public-story checks in isolation.
2. On one representative record, compare the rendering to each distinct relevant design at the same content width, data, state, locale and scale. Look at reading order, alignment, typography, whitespace and the visual prominence of the action. Inspect the element whose geometry accounts for a discrepancy. Fix the material difference and repeat. Disclose unavoidable differences in the evidence.
3. In one **mounted** instance, enter the meaningful state, resize the parent through the change of layout and finish the action. Observe its user-visible result or the value delivered to the public callback. If a change moved stateful content to a new parent, run the closest existing behavior check. For a changed interaction, complete the gesture through its stable end state using the input methods it supports.
4. With the second record, vary the container through the supported range. Probe the width where the content is under pressure and capture that state. Check visible text, neighboring regions, overflow and reachability. Resize the viewport as well if host behavior depends on it. A sweep can locate a suspect width; verify the actual content and action there.

**Hand off the proof.** Give the direct story or host route, exact record and measured container width, matching reference and rendered image, and the result of the primary action. Keep evidence focused on distinct states or defects. State which remaining question requires a real consumer and what prevented any requested check. If a coordinator delegates verification, a fresh observer gets the journey, public route, data and design and independently replays it.
