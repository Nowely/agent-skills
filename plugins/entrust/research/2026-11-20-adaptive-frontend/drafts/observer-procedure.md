# Entrust live prober at the first working slice

The coordinator assigns one user journey that is about to be implemented in more than one host. Use this handoff when observing the first host could change substantial remaining work.

1. Before product edits, open the ordinary entry and the closest functioning precedent. Play through the action as a user. Capture a small baseline showing what is visible immediately after the initiating gesture, which meaningful action comes next, and how the user knows it completed. Record the fixture, actual viewport or container, platform, source revision and screenshot hash. Keep unknowns explicit.
2. At the handoff the writer stops editing. Independently replay that journey in the first working host using the agreed local browser. Compare with the captured behavior and with the old host where their data or selection semantics differ. A resemblance in code or a successful final callback alone cannot establish the experience.
3. Within the assigned time, return one compact receipt. Include a link to each decisive observation, any user-visible mismatch with its reproduction, or an explicit statement of which checks passed. Keep the writer free to choose the implementation. Flag owner decisions separately from defects.

Use a clean browser context for a public story. An authenticated product stand uses its configured persistent profile with one active owner. Count both visits in the delivery budget. The coordinator resumes the writer once feedback has been delivered.
