# Content eval harness

`content.official.mjs` stages a copy of `plugins/terse/plugin` and a generated official eval suite under `$TMPDIR`. It does not run Claude unless given `--run`. The case file is a JSON array with unique lowercase slug `id`, `candidate`, `set`, and `stratum`; a `prompt`, hidden `key`, `allowedTools`, and nonempty `graders`; optional `fixtures`, `history`, `maxTurns` (default 15), `timeoutSeconds` (default 300), and `recipient`. Each grader is `llm` with `criteria` and optional `focus` (`last_message` or `trace`), or `tool_used` with `tool` and optional `input_match`, `min`, and `max`. `recipient` has its own `allowedTools` and `graders` for a later delivery test. The generated case name encodes `candidate::set::stratum::id` so result JSON retains group labels even if Claude Code omits tags. The key appears only in LLM grader bodies beneath `## Answer key`; prompts and fixtures carry only task material. A `clarity_loaded` Skill grader reports exposure separately from the outcome.

A variant JSON has a name and one or more `{file, find, replace}` edits, with `file` relative to the staged plugin root. Each `find` must occur exactly once. `content/variants/noop.json` is a control variant with a real one-word body change in `skills/clarity/SKILL.md`: “few” becomes “fewer.” It is intentionally small, but the model can read it. `--force-skill terse:clarity` leaves each prompt unchanged and writes `execution.append_system_prompt` with “Before you answer, load the terse:clarity skill with the Skill tool and apply it to your answer.” It also grants `Skill` in `allowed_tools` if absent. This measures the page after requested exposure; without that flag the prompt measures natural invocation as well as page effects. `--force-skill` and `--baseline` cannot be combined. Without `--baseline`, the generated command adds `--ablation none` for one with-plugin arm. With `--baseline`, official eval runs with and without the plugin; the `clarity_loaded` Skill grader should be reported but excluded from two-arm scoring by Claude Code. The coordinator should verify that exclusion in the paid result.

When fixtures exist, `fixture.sh` reconstructs their UTF-8 bytes from base64 arguments in a fresh workspace. It uses Node's `Buffer` and quoted shell arguments, so fixture text cannot expand in Bash or collide with a heredoc delimiter. For history, the harness writes one JSONL line per prior turn with a common `sessionId`, distinct `uuid`, linked `parentUuid`, `timestamp`, `type`, `message`, `cwd`, `version`, `userType`, `isSidechain`, and `gitBranch`; user lines also have prompt metadata, and assistant lines have a text message with model, message ID, end-turn marker, and usage. The `cwd` is `.` so the resumed run can use its own workspace. The saved official docs say only that `context.history_file` is a `.jsonl` transcript. Inspection of key structure in local private Claude Code 2.1.273 transcripts supplied the line shape; no private text was copied. The local Claude Code 2.1.280 binary passes the resolved `history_file` path to `--resume` and its loader reads a conversation chain and embedded `sessionId`, so `history.jsonl` need not have a UUID filename. The prior paid smoke rejected the minimal lines before the first turn. The coordinator must verify this richer synthetic transcript resumes correctly, that the new system prompt causes a Skill call, and that the judge uses the key as intended. `--history-inline` quotes prior turns into the prompt and omits `context.history_file` as a fallback.

`content.official.mjs` prints the staged plugin path, output directory, and exact command. `--run` executes it and writes `result.json`, an HTML report, and kept traces under a new `$TMPDIR` output directory. `--judge-model` defaults to `sonnet`, `--runs` to 3, and `-j` to 3. Run `content/cases/pr35-field.json` with `--judge-model opus`: on its saved answers a Sonnet judge agreed with the expected verdicts on 7 of 12, failing answers that met list-first and facts-correct word for word, and an Opus judge on 12 of 12 ([research](../research/2026-09-29-clarity-field-report/results.md)). Every agent run and every LLM judge vote spends Claude tokens; keep these runs manual and out of CI. `content.compare.mjs A.json B.json` compares the with arms of two results; with one file, `--arms with,without` compares its arms. It prints per-case grader pass counts and mean outcome score, candidate and stratum totals, and an exact two-sided sign test over non-tied case differences. `--json FILE` writes the same comparison as JSON. It rejects partial results and runs whose paid graders were skipped. It recomputes outcome scores from scored graders after removing `clarity_loaded`, so invocation cannot count as answer quality even in one-arm results.

`content.recipient.mjs --from OUT --cases FILE` reads `OUT/result.json` and each with-arm run's `tracePath` from a first K3 brief run. It takes the last assistant text (or the stream's final result text), makes one recipient case per source run, carries across the source fixtures and key, and applies that case's `recipient.allowedTools` and `recipient.graders`. It stages a minimal plugin with no skills and uses `--ablation none`, so the recipient is a plain agent. The source trace directory is read only. It also stages and prints by default; `--run` starts the paid eval. The coordinator should verify that the kept trace's final message is the brief intended for the recipient.

Offline check: `node content.selftest.mjs`. Manual paid smoke, after inspecting the staged suite: `node content.official.mjs --cases content/examples/smoke.json --variant content/variants/noop.json --run`. The normal stage-only form leaves a copy under `$TMPDIR` for review.

`--criterion-only` replaces the closing line of every `llm` grader ("FAIL if it omits or contradicts a required fact in the answer key") with an instruction to judge only the grader's own criterion and to use the key for the facts it needs. Use it when the key holds facts a response must not repeat, such as a recipient's hidden finding beside a brief's grader; `content.recipient.mjs` always uses it. Keep it the same in both arms of a comparison.
