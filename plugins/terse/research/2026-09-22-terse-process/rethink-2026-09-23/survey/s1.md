Method note: word counts are whitespace-token counts (`text.split()`), verified against the brief's stated
933 words for `00-current.md` (exact match). Heading counts strip fenced code blocks first, so shell
comments (`# like this`) inside install snippets aren't miscounted as headings — an uncorrected first pass

GitHub-hosted docs were fetched as raw markdown (`raw.githubusercontent.com/<owner>/<repo>/HEAD/<path>`);
the three vendor doc pages were fetched as their raw-markdown source (`<url>.md`, confirmed to exist and
differ from — be fuller than — the HTML-rendered version), not the rendered HTML.

`/terse:audit`, `/terse:rethink`, `/terse:rewrite` in one glance instead of reading three full paragraphs to
find the one they need. Place: replacing or preceding the current "## What each one does" prose block. Of

round, verbatim in `purpose.md`: "no table or list of the skills as plugin READMEs have."

**A "why this instead" clause naming the alternative.** Purpose: satisfy purpose.md's "why they would want
it" before Install. Place: folded into the opening paragraph, or a short section right after it — terse's
933-word budget likely doesn't afford `trailofbits`'s or `entrust`'s full dedicated section. Only 2 of 10
sampled documents carry a dedicated section for this. The content already exists and is unused: `audit.md`'s

asking Claude to "improve my README") and "Why this instead" (5 named reasons), and none of it is reflected
anywhere in `00-current.md`.

**A stated first command/outcome at the end of Install.** Purpose: satisfy purpose.md's "know what to
type... to start," not just to install, and "know which of the three skills to run first." Place: the last
lines of "## Install," or a short section immediately after it. 9 of 10 sampled documents show some form of
this (a worked example, a stated outcome, or a numbered first-step) right after their install instructions;
only `obra/superpowers` defers it several sections later, and terse's current README ends Install at

## Slice 1 — not to copy

**A full configuration reference inlined into the README body, instead of linked out.**
`jarrodwatts/claude-hud`'s (28,133★) "### Options" table alone runs to roughly 110 lines and is the largest
single device found in any sampled document; the whole README reaches 5,412 words — 5.8× the size of
`00-current.md` — for what `wshobson/agents` (39,908★, a much larger marketplace) achieves in 1,155 words by
linking to `docs/*.md` instead. Harm: a reader who wants License or Development/Contributing information (both
present, both at the very bottom) must scroll past the entire options table first.
URL: https://raw.githubusercontent.com/jarrodwatts/claude-hud/HEAD/README.md, `### Options` section.

**A blanket disclaimer that hedges every claim in the document at once.** `anthropics/skills`'s (177,800★)
"## Disclaimer" states "the implementations and behaviors you receive from Claude may differ from what is
shown in these skills" as a standing, undifferentiated caveat over the whole repository. Harm, specific to
this project: `terse` exists to replace exactly this move — a hedge applied to everything is indistinguishable
from a hedge applied to nothing, and the project's own writing rule (recorded in this session's memory,
`feedback-qualification-is-antipattern.md`) is that a sentence needing a caveat says too much; the fix is to
make the specific claim true where it's stated, not to blanket-hedge above it.
URL: https://raw.githubusercontent.com/anthropics/skills/HEAD/README.md, `## Disclaimer` section.

## Slice 4 — what the vendor expects, synthesized

**What a plugin README must carry, per the vendor:** installation instructions and usage instructions —
literally items 1 of a 4-item "Share your plugins" checklist in `code.claude.com/docs/en/plugins`. Nothing
mandates a comparison-to-alternatives section, a "what it will/won't do" section, or measurement evidence;
those are the owner's bar (`purpose.md`, `audit.md`), above the vendor's floor, not contradicted by it.

**Where the vendor puts install:** always a top-level heading placed after one or two short framing
sections, never buried; always the exact two-line command pair (`/plugin marketplace add ...` then `/plugin
install ...`) in a fenced block, in every vendor-authored example fetched (`plugins/README.md`,
`claude-plugins-official/README.md`). The vendor's own reference plugin (`example-plugin`) skips Install
entirely because it isn't meant to be installed standalone — the one deliberate exception, and it explains
why.

**Where the vendor puts commands/skills:** at marketplace (multi-plugin) scale, a Name|Description|Contents
table, with per-component-kind bold labels packed into the Contents cell (`plugins/README.md`). At
single-plugin scale, the vendor's own template (`example-plugin`) uses a flat 3-line bullet list under
"## Usage," one line per component, phrased as behavior ("activates based on task context"), not as a
name-only inventory.

**Which devices the vendor uses:** fenced code blocks for every install/usage command without exception
(never a command described only in prose); a directory-tree code block for physical layout; a table only
once there's more than a handful of items to compare (a marketplace listing, an LSP language matrix, a
field-precedence rule) — never for a single plugin's 2–3 components; a blockquote for the one standing trust
warning (`claude-plugins-official`). Badges appear only on the CLI product itself

authored uses a badge.
