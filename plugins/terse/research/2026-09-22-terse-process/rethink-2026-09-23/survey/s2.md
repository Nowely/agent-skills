# S2 survey — stage 1 of the `terse` README rethink

Slices: (3) the most used, regardless of genre; (6) the adopt-nothing slice. Date: 2026-09-23.

**Fetched:** 13 GitHub API lookups (`stargazers_count`, all HTTP 200) to rank candidates; 10 READMEs
fetched at HEAD (`raw.githubusercontent.com/<owner>/<repo>/HEAD/README.md`, all HTTP 200, 0 failures).
The same 10 documents back both slices.

**Methodology correction, disclosed because it bears on "fetch, do not recall":** the first pass used
the `WebFetch` tool as instructed. For 6 of 10 URLs (ripgrep, prettier, cli/cli, esbuild, httpie, jq) it
returned genuine raw text. For the other 4 (fzf, bat, ruff, black) — the larger files — it returned
fabricated summaries dressed as the source: invented headings ("## Key Characteristics", "## Core
Functionality") not present in the real document, zero code blocks, zero links, zero badges, generic
"According to the documentation..." prose. This was caught by structural comparison (a real popular
tool's README is never that link-free) before anything was cited, confirmed with one direct `curl` (fzf's
real first line is `<div align="center"><img ...>`, not the invented H1 WebFetch supplied), and corrected
by re-fetching **all ten** via `curl` into `R/survey/fetched/*.md` and computing headings, word counts,
first-words and device counts mechanically from the saved raw text, so every number below is reproducible
from the saved files, not read off a model's paraphrase. Word counts are `wc -w` over the raw fetched
file (a standard, uniform proxy that also counts URLs and markdown syntax as tokens — applied identically
to all ten and to terse's own README for comparison). "Visible words" strips fenced code, markdown/HTML
images, and HTML tags, and converts `[text](url)` to `text` — an approximation of what a reader actually
sees rendered, used only for the first-100/150-word quotes.
