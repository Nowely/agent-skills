# Examples of reader-side changes

These are paraphrased general mechanisms, not templates. The outcome label says what was observed; moving on is not approval. Genre-specific pairs live in their own [notes](genres/). These pairs come from `plugins/terse/research/2026-09-26-writing-replication/publication/issue-comment.md`.

<a id="claim-strength"></a>**Strength of a claim.** Before: a comment gave a precise slowdown factor and a later report pinned CI to one CPU count. After: the slowdown was described without a false precision and the CPU count became a range. The owner chose the bounded form because the exact value was not guaranteed. Source: P05.

<a id="labels"></a>**A label from earlier.** Before: a plan used experiment and option codes without their meanings. After: a short legend restored the meanings. The owner had explicitly said they did not remember the labels; the conversation then moved on. Source: P11.

<a id="choices"></a>**A real choice.** Before: a long verdict table buried its recommendation below. After: each choice showed options, consequences and a visible recommendation with its reason. The owner made a different choice for a stated reason. Source: P16.

<a id="change-and-effect"></a>**Change and effect.** Before: a proposal grouped page edits by mechanism. After: it grouped concrete changes by where the owner would notice them. The owner praised that form. The effect still needs the actual edit when the reader asks to see it. Source: P17.
