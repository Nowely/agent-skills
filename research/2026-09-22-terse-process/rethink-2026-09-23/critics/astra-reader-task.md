## Counting rules and the two tasks

I number **content sections S1 onward in reading order**, combining the bare product title with the opening. Unheaded tables, excerpts, and route lists count separately when the structure allocates them separately. Thus 01 and 03 are shifted one position from their title-inclusive tables. Numbering is spelled out in each review.

In each question map, `S2+S5 [2/3]` means two sections supply the answer and three section boundaries separate the first and last (the reader spans S2–S5). It is not a measured click count. A single home is `[1/0]`; the S number still shows how far down a linear reader must get. `partial` means those sections do not yet assemble the full keyed answer. `none` means no allocated answer, not zero effort. A source citation in “Rests on” is not content allocated to the future README.

The seven required answers are: Q1 the two installation commands; Q2 all generated/diagnostic writes separately from applying the document; Q3 audit first for an existing uncertain document, including the possibility of stopping without rewriting; Q4 audit supplies findings, a separately invoked rewrite supplies a whole draft and diff, replacement waits; Q5 guards against undoing fixes, not immunity; Q6 shortening is not the objective; Q7 the documentation does not establish equivalent Russian-language behavior. The 6% observation supports Q6 but is not necessary to answer its decision. Q7 must not turn into either a confident yes or a confident no.

**Task A — install and start the first audit:**

- A1: identify the applicable runtime/session prerequisites and the described install’s behavioral scope.
- A2: add the marketplace and install with the two shell commands, in the correct environment.
- A3: move into the Claude Code conversation for the intended document; distinguish the shell from slash commands and supply/select that document.
- A4: choose audit, understand what it reads/writes and the agent/model consent before execution.
- A5: invoke it and handle its first exchange; identify what counts as having started successfully.
- A6: recognize the report/location handoff and the option to stop when no change is warranted.

A5 is TA’s actual endpoint; A6 assesses whether the advertised result gives that action a usable next step. The isolated configuration and authentication transfer in TA were test-harness needs, not automatic requirements for every README reader. The README still needs an intelligible normal-session transition. Trust/tool prompts may be linked if needed; copying the harness internals would violate the owner’s economy requirement.

**Task B — from an audit to a candidate without touching the document tree:**

- B1: establish whether the installed version can meet **no tree writes**, including untracked directories and diagnostic files; otherwise stop before invoking rewrite.
- B2: identify the audit report/folder to hand over and confirm the document’s agreed shape, or take the conditional rethink route.
- B3: start rewrite in the correct environment with that input; make clear what the user supplies and what the skill creates.
- B4: understand/accept agent work while preserving the no-tree-write boundary.
- B5: locate the returned whole draft and diff, both outside the tree for this task.
- B6: review the changes and the limits of the checks; decline application, leaving the document tree unchanged.
- B7: know how to stop/continue and, if assessing again, assess the candidate with comparable questions rather than accidentally the unchanged original.

The historical TB only achieved a weaker **plan** by refusing `ISSUES.md` and accepting an untracked `research/` directory. That does not satisfy this task. On that audited recipe B1 must stop; no new README wording can make the route safe. Current feasibility is **unknown**.
