# Stage 1 survey — README rethink, slices 5–7

Date: 2026-09-24. This survey is of AI-coding-agent/project README Markdown, not of the product source. The document being designed does not yet exist. The owner needs a GitHub front door that lets a reader select one of three delivery routes, make one first run, and locate a next slash command.

## Method, corpus, and limits

I fetched each README directly as raw Markdown at its URL below, saved it in `fetched/`, and counted the saved bytes. I also fetched the named repository's GitHub API record to obtain `stargazers_count` and `forks_count`; that JSON is saved beside the Markdown and its bytes are stated. No rendered README or summary service was used. Counts are from these saved files: words are raw `wc -w` tokens; headings exclude lines inside fenced code; a table is a Markdown separator row; bullet lists are `blocks/items`; a code block is a matched triple-backtick pair; badges are image links used as badges; images exclude those badges. “First 100” is the first 100 whitespace-delimited source tokens beginning with the first prose sentence (line breaks normalized only).

The genre corpus is seven unique documents (slice 5 plus the additional slice-6 documents); the three owner exemplars are deliberately not included in its M. Use is ranked by saved GitHub-API star count, not by appearance. API values are observations in this run, not all-time counts.

Fetch failures: none. There are ten README documents, ten saved raw Markdown files, and ten saved API records.

### What they solved, ranked by use

#### Claude Code — a `Get started` section whose purpose is to eliminate obsolete or platform-inappropriate installers, placed immediately after identity

The saved source labels npm deprecated, marks MacOS/Linux and Windows choices recommended, then gives `claude` as step 2. The split is five bold method labels inside one numbered installation step. This is the clearest compact pattern for a reader who has not selected a route.

#### Codex — an opening route chooser whose purpose is to send IDE, desktop, web, and CLI readers to different products before CLI instructions, placed before `Quickstart`

The three “If you want …” lines are a product-form selector, then Quickstart is explicitly CLI-only and finishes with `codex`. This solves wrong-route selection before installation rather than explaining every form in the same section.

#### Gemini CLI — an `Installation` section whose purpose is to choose a package path and execution mode, placed after a brief value statement

Five method headings distinguish instant `npx`, global npm, Homebrew, MacPorts, and restricted Anaconda. A later Authentication section makes the first interactive `gemini` run explicit. Its route labeling is useful, but it delays the simplest next action behind value and installation detail.

#### OpenHands — a `Quickstart` section whose purpose is to choose a trust boundary and deployment environment, placed after the product explanation

Three Option headings distinguish unsandboxed local, Docker sandbox, and source. Warnings tell the reader when agent-server filesystem access is broad; the Option 1 fence includes `agent-canvas`. This is a good model where a route choice has safety consequences.

### Not to copy

#### Do not copy an opening badge-and-locale wall before the route chooser

At https://raw.githubusercontent.com/anomalyco/opencode/HEAD/README.md, three badges, a logo, 22 locale links, and a linked screenshot occur before `### Installation`; the first 100 source words are still mostly markup and locale links. Harm: a new reader cannot use that visual mass to choose an installation route, and the ten alternatives arrive as comments within one fence. For the owner's document, put a three-route chooser before badges, screenshots, and language navigation.

#### Do not copy volatile quota, model, and calendar release claims into the first decision screen

At https://raw.githubusercontent.com/google-gemini/gemini-cli/HEAD/README.md, `Why Gemini CLI?` leads with 60 requests/min, 1,000 requests/day, Gemini 3, 1M tokens; `Release Channels` specifies weekly/daily UTC publication times. Harm: these version- and policy-bound claims can stale while a reader is still looking for an install route. Put stable route criteria and commands first; link changing quotas, models, and release policy outward.

#### Do not copy a two-form install section with no explicit first command or chooser criterion

At https://raw.githubusercontent.com/block/goose/HEAD/README.md, `Get started` offers a desktop download or a CLI installer, but the saved source does not say which is for which task and does not show what to type after installation. Harm: the reader leaves the front door still unable to complete a first run. Each owner route needs its first action, and the shared next chat command needs its own step.

#### Do not copy route tiles that are only badge links

At https://raw.githubusercontent.com/continuedev/continue/HEAD/README.md, the three delivery subsections contain marketplace/release/source badge links but no install command or verification. Harm: an archived product may need link-outs, but a fresh reader cannot complete a route from the README and cannot tell whether a linked artifact is the intended one. Use a command or explicit click path plus an expected first result for every route.
