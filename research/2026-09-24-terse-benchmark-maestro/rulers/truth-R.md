## Refuted claims, ranked by what a reader who acted on them would lose

1. **Line 55, the MCP server entry.** Servers a VS Code user adds to `.vscode/mcp.json` are deleted at the next editor start once Maestro's entry is in the file, and again at each later start. The only message shown is "MCP server configured automatically". A `.vscode/mcp.json` containing a comment is replaced at the first start. In Cursor the entry never lands in `.cursor/mcp.json`, the file line 70 says Cursor reads.
2. **Line 56, the Zero-Defect block.** Switching the mode on writes 74 lines into CLAUDE.md, and into .cursorrules in Cursor, not 8 rules. Among them is an order to invoke /agent-workflow and run /teach-maestro first, which the agent then reads in every session. Switching the mode off does not remove the block from a file Maestro created.
3. **Line 66, @maestro /teach-maestro.** An extension user who follows the chat route never gets `.maestro.md`. The interview cannot get past its first question, and nothing is saved, so every later command runs without project context.
4. **Lines 129, 130 and 9, memory across sessions.** In VS Code's chat, /capture saves no summary yet logs "completed", and /recap has nothing to read back. The user believes the session was kept, and it was not.
5. **Line 133, "~tokens" and "~cost".** A user who budgets from the audit log or from /reflect sees 0 to 11 input tokens recorded for requests of thousands, so spend is understated.
